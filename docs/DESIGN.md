# me 설계

> 라우팅은 내가 하고, 개발은 대화로 하고, 웹은 그 대화를 어디서든 이어 가게 해 준다.
> 각 하네스는 자기 집에서 일하고, 오케스트레이터는 코드를 만지지 않는다.

최종 갱신: 2026-10-09 · 상태: 첫 조각 구현 완료 (9절 완료 기준 충족, 실행 방법은 README)

## 1. 철학

- **모델은 자기 하네스에서 가장 완벽하다.** Claude는 Claude Code에서, Codex는 Codex에서 가장 잘한다.
- **하네스는 여러 개를 골라 쓴다.** 고르는 기준은 작업 적합성, 비용, 무료 모델 여부다. 필요하면 하네스를 더 설치한다.
- **라우팅 판단의 주인은 사용자다.** 시스템은 그 판단을 어디서든 빠르게 실행하고 결과를 보여 준다.
- **개발은 대화로 한다.** IDE 대신 에이전트와의 대화가 인터페이스다.
- **이미 있는 좋은 부품 위에 쌓는다.** Ghostty, Herdr, brgr, Tailscale은 대체하지 않는다.
- **안정화는 쓰면서 한다.** 사용자가 매일 쓰면서 바로 이슈를 올린다.

## 2. 반드시 지킬 제약

| 제약 | 내용 | 집행 방식 |
|---|---|---|
| Claude ToS | Claude 구독은 Claude Code 안에서만 쓴다. GJC 등 서드파티 하네스에서 Claude 모델을 쓰지 않는다 | GJC 허용 모델 목록에서 Anthropic 모델 제외. Claude가 필요하면 Claude Code 워커에 위임 |
| head는 코드를 만지지 않는다 | head는 판단, 라우팅, 보고만 한다 | 문서로 부탁하는 게 아니라 GJC `--tools` 화이트리스트로 편집 도구를 뺀다 |
| AGPL 격리 | gajae-way(AGPL-3.0)는 문서와 동작만 참고한다. 코드는 보지도 옮기지도 않는다 | 제품화 가능성이 있으므로 예외 없음 |
| 커널이 유일한 통로 | 플러그인끼리 직접 통신하지 않는다 | 모든 요청과 이벤트는 커널을 거친다. 그래야 저널과 권한이 의미가 있다 |
| 공개하지 않는다 | 웹은 `127.0.0.1`에만 연다 | 원격 접근은 Tailscale 경유로만 |

## 3. 전체 구조

```
┌──────────────── 플러그인 ────────────────┐
│ web · brgr · gjc-head · slang · summarize │
│ jev · (나중) acp · discord · ops-mcp ...  │
└───────────────────┬──────────────────────┘
                    │ JSON-RPC (stdio/socket)
┌───────────────────┴──────────────────────┐
│ 커널: 실행기 · 중계 · 저널 · 상태 · 권한 · 프로토콜 │
└───────────────────┬──────────────────────┘
                    │
              SQLite (저널 + 상태)
```

층으로 보면 이렇다.
- **일하는 층**: Claude Code, Codex, GJC, OMP, OpenCode, Cursor, Pi, Senpi 등. 각자 자기 집에서 일한다.
- **지휘 층**: GJC head. 코드를 만지지 않는다.
- **관제 층**: localhost 웹이 먼저다. 메신저(Discord, Slack)는 나중에 플러그인으로 붙인다.
- **운영 층**: 프로세스 상태 MCP, 원격 테스트 머신, 설정 관리. 모두 나중에 플러그인으로 붙인다.

## 4. 커널

기준: **플러그인에 맡기면 플러그인끼리 서로를 망가뜨리거나 우회할 수 있는 것만 커널이 한다.**

| 커널이 하는 것 | 내용 |
|---|---|
| 실행기 | 매니페스트를 읽고 플러그인을 띄우고 감시하고 재시작한다. 계속 죽는 플러그인은 격리하고 알린다 |
| 중계 | 요청/응답과 이벤트 발행/구독. 플러그인 사이의 유일한 통로 |
| 저널 | 커널을 지나는 모든 이벤트를 순서대로, 지우지 않고 기록한다 |
| 상태 | 저널에서 계산한 현재 상태. 엔티티 스키마는 플러그인이 등록하고, 커널은 "에이전트"나 "작업"이 무엇인지 모른다 |
| 권한 | 매니페스트에 선언한 능력 밖의 요청을 막는다. 위험한 동작은 사용자 승인 관문을 거친다 |
| 프로토콜 | JSON-RPC 규격, 버전 협상, 플러그인 등록 절차 |

커널이 **하지 않는 것**은 다음과 같다.
- 화면
- AI 호출
- 하네스에 대한 지식
- 위임 판단
- 사용자 인증 방식: 인증 플러그인이 신원을 알려 주고, 커널은 그 신원으로 권한만 집행한다
- 비밀 값 저장: 자격 증명은 파일로 두고 경로만 넘긴다

플러그인을 띄우는 기본 실행기는 플러그인이 될 수 없다. 나머지는 전부 플러그인이다.

## 5. 플러그인

### 프로토콜

상세 규격: [PROTOCOL.md](PROTOCOL.md), 타입: [`protocol/types.ts`](../protocol/types.ts)

- 기본은 **자체 JSON-RPC**다. stdio 또는 Unix 소켓 위에서 돈다. 형식은 MCP와 LSP를 참고하되 이벤트, 생명주기, 권한은 우리 필요에 맞게 정의한다.
- **MCP 어댑터**: 기존 MCP 서버를 플러그인으로 감싼다.
- 플러그인은 별도 프로세스이고 언어는 자유다. 커널과 웹은 TypeScript, brgr는 Rust이고, 필요하면 Go나 Python도 된다.
- 이 프로토콜은 플러그인이 늘어난 뒤에는 바꾸기 어렵다. 가장 신중하게 정한다.

### 실행 방식 (C)
- **로컬 플러그인**: 커널이 직접 띄우고 관리한다. 첫 조각은 이 방식만 만든다.
- **원격 데몬**: 각자 실행된 뒤 커널에 접속한다. 원격 서버 기능을 붙일 때 추가한다.

### 매니페스트
- 이름, 버전, 실행 명령, 선언하는 엔티티 스키마, 발행/구독하는 이벤트, 요청하는 권한을 적는다.
- 권한은 굵은 단위로 시작하고(`read-state`, `delegate`, `shell`, `network` 등) 필요할 때 쪼갠다.

## 6. head와 판정 흐름

head는 **GJC**이고, 백그라운드에서 **json 모드**(`-p --mode json --no-mcp --tools <허용 목록>`)로 돈다. ACP 모드는 도구를 제한할 수 없어 head에 쓰지 않는다([검증 결과](../spikes/gjc-headless/FINDINGS.md)). 실제로 노출된 도구는 실행마다 이벤트에서 확인하고, 허용 목록 밖의 도구가 보이면 실행을 중단한다. 판정은 여러 플러그인으로 나뉜다.

1. **slang 플러그인**: 사용자의 줄임말을 사전으로 치환한다. 예: `ㄱㄱ`→시작하자, `ㅇㅇ`→응, `ㄴㄴ`→아니, `ㄹㅇ`→진짜, `억까`→일부러 반대 입장에서 공격해 봐. LLM을 쓰지 않으니 비용이 없다.
2. **summarize 플러그인**: LLM 한 번으로 영어 구조화 요약을 만든다. 이 요약이 위임 지시서의 초안이 된다.
3. **jev 플러그인**: OpenRouter의 `typesafe/jev-router`를 쓴다.
   - Noul 모드로 "이 작업은 간단하다"가 참일 확률을 받는다.
   - Choice 모드로 1차 라우팅 후보를 받는다.
   - 질문은 영어, 긍정형으로 고정한다. Jev는 한국어와 부정문에 약하다.
4. 간단함 확률이 기준 이상일 때만 head가 직접 처리한다. **애매하면 위임한다.**
5. 판정 결과와 근거는 모두 저널에 남긴다. 웹에는 "이렇게 이해했어요"(정리된 한국어)와 판정 배지를 보여 준다.

Claude가 필요한 작업은 brgr를 통해 별도 pane의 **Claude Code**에 위임한다.

## 7. 웹 플러그인

- React를 쓰고, Bun 내장 번들러와 개발 서버를 쓴다. Vite는 필요해질 때 추가한다.
- **화면 두 개**
  - **한눈에 보기**: 머신, 하네스, 작업, 플러그인 상태
  - **채팅**: head와의 대화
- **답변 렌더링**
  - 마크다운: 표, 코드 블록, 문법 강조
  - 스트리밍
  - 도구 사용과 위임은 접을 수 있는 카드로 보여 준다
  - 위임 결과 카드에는 수락, 거절, diff 보기 버튼을 붙인다
- **이슈 버튼**: 누르면 그 순간의 관련 엔티티, 최근 이벤트, 로그를 자동으로 첨부해 GitHub 이슈를 만든다. 사용자는 한 줄만 쓴다.
- **보안 최소선**
  - `127.0.0.1`에만 바인딩한다
  - `Host`/`Origin` 헤더를 검사한다
  - 상태를 바꾸는 요청에는 CSRF 토큰을 요구한다
  - 로컬 접근 토큰을 둔다

## 8. 기술 결정

| 항목 | 결정 |
|---|---|
| 런타임 | Bun (커널, 웹) |
| 저장소 | SQLite 파일 하나 (저널 + 상태) |
| 웹 | React + Bun 내장 번들러 |
| head | GJC json 모드 (`--no-mcp` + `--tools`, 노출 도구 감시, 기본 모델 명시 고정, Anthropic 모델 제외) |
| 판정 | Jev via OpenRouter |
| 위임 | brgr 플러그인이 기본, ACP는 나중에 별도 플러그인 |
| 네트워크 | localhost 전용. 원격은 Tailscale(`tailscale serve` + 신원 헤더). 이 부분은 교체 가능해야 한다 |

## 9. 첫 조각

**구성**: 커널 + 플러그인(web, brgr, gjc-head, slang, summarize, jev)

**완료 기준**: 다음이 모두 되면 "오늘부터 매일 쓴다"고 말할 수 있다.
- localhost 웹에서 상태가 한눈에 보인다
- 웹에서 GJC head와 채팅할 수 있다
- head가 brgr로 Claude Code에 일을 위임한다
- 웹에서 결과를 수락하거나 거절할 수 있다
- 모든 이벤트가 저널에 남는다
- 이슈 버튼이 동작한다

## 10. 미해결 (확인 전에는 사실로 다루지 않는다)

- ~~`gjc --mode acp`/`json`이 headless로 쓸 만한 구조화 이벤트를 실제로 내보내는가~~ → 둘 다 내보낸다. 편집 차단은 json 모드에서만 된다. [FINDINGS](../spikes/gjc-headless/FINDINGS.md)
- `gjc quick-lane classify`와 Jev 판정 비교
- GJC `--tools`에 쓸 수 있는 도구 이름 전체 목록 (head 허용 목록의 기준)
- Jev의 실제 호출 비용 (OpenRouter 목록에 가격이 `-1`로 표시됨)
- head가 죽었을 때의 재시작과 세션 이어 가기 (`--continue`, `--resume`)
- head의 모델 공급자 약관: Claude가 아닌 구독을 서드파티 하네스에서 써도 되는가
- 하네스 사이의 상호 조회와 메시지: brgr `message`와 ACP로 어디까지 되는가
- 원격 리눅스 QA용 브라우저 런타임: 지금 QA 규칙은 Mac 앱(Ego Lite, Aside) 기준이다
- gajae-way 문서에서 뽑은 안정성 체크리스트(보내기 전에 기록, 불확실한 전송은 중복으로 표시해 재전송, 대화별 세션 분리, 동시 메시지 순서 보장)를 메신저 플러그인 전에 테스트로 만든다

## 11. 나중에

- 플러그인: Discord, Slack, ACP, 운영 MCP(읽기 전용부터), 원격 테스트 머신, 원격 데몬, Tailscale 인증
- **설정 관리 플러그인**
  - 플러그인, MCP, Skills, Hook, `AGENTS.md`를 원본 한 곳에서 관리하고 하네스별 형식으로 내보낸다
  - 항목마다 공용 여부를 정한다
  - 주의: 인증은 하네스별로 따로인 경우가 많다. 이름이 같아도 일부러 내용이 다른 항목이 있다
- 프로젝트 자체 라이선스 (공개할 때 정한다)

## 참고한 기존 도구 (조각)

- Agent of Empires, CloudCLI, Omnara: 여러 하네스를 웹과 모바일로 관리
- Superset, Crystal, Claude Squad: 병렬 worktree 관리
- skillcp, agentsync, Synctax: 설정 동기화
- gajae-way: GJC를 메신저 페르소나로 띄우는 게이트웨이. 코드는 쓰지 않고 문서만 참고한다

차이점은 하네스를 대체하지 않고 지휘한다는 것, 그리고 Herdr와 brgr 위에서 돈다는 것이다.
