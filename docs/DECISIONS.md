## 0. 정체

- **나를 위한 개발 OS.** 새로 만드는 게 아니라, 이미 쓰는 조각(Herdr, brgr, 하네스, Tailscale)을 얇은 커널로 맞추는 엔진이다.
- **Orca 같은 ADE를 해체해서 내 방식으로 다시 조립한 것이다.**
  - ADE는 앱 하나가 자기 패러다임을 사용자에게 입힌다.
  - me는 도구가 **내 패러다임**을 입는다. 머릿속에만 있던 그 패러다임을 꺼내 도구로 관리한다.
- 이름은 **`me`**. 나중에 방법론 포맷은 **`.me`**로 둔다. 쓰는 사람마다 그 사람의 "나"가 된다.

### 원칙
- **모든 기능은 플러그인이다.** 커널은 플러그인끼리 망가뜨리거나 우회할 수 있는 것만 한다.
- **판단은 다이얼이다.** 에이전트에게 끝까지 맡길 수도 있지만, 사람은 언제든 판단을 되찾을 수 있다.
- **web-first는 어렵게 만들지 않겠다는 선언이다.**
- **속도가 중요하다.** 안정화는 쓰면서 이슈를 올리는 방식으로 한다.

### 차별점
- **모델이 아니라 하네스를 라우팅한다.** 모델은 자기 하네스에서 가장 완벽하기 때문이다.
- **`me adapt`로 무엇이든 붙인다.** 순서는 마켓플레이스 → 범용 브리지 → 에이전트가 토큰을 써서 어댑터 작성이다(8절).
- **내 도구든 남의 도구든, me에 붙으면 내 것처럼 쓴다.**

## 1. 철학과 방향

- **모델은 자기 하네스에서 가장 완벽하다.** Claude는 Claude Code에서, Codex는 Codex에서, Grok과 Cursor 모델은 Cursor에서 가장 잘한다.
- **하네스는 여러 개를 골라 쓴다.** 고르는 기준은 세 가지다.
  - 작업 적합성: GJC는 장기 루프, 인터뷰, 리서치. Codex는 insane-* 플러그인. 리뷰는 Codex Astra에 위임.
  - 비용을 고려한 모델 선택
  - 무료 모델 활용: OpenCode, Cline
- **필요하면 하네스를 더 설치한다.** Senpi(`@code-yeongyu/senpi`)에 관심이 있다. 아직 설치하지 않았고, 설치하면 `pi` 명령이 기존 Pi와 충돌한다.
- **라우팅 판단의 주인은 사용자다.** 시스템은 그 판단을 어디서든 빠르게 실행한다.
- **개발은 대화로 한다.** IDE를 거의 쓰지 않고 Herdr 안에서 에이전트와 대화하며 개발한다.
- **메신저처럼 일하는 리듬이 좋다.** Meta Muse를 쓰며 확인했다.
- **안정화는 쓰면서 이슈를 올리는 방식으로 한다.** 기능을 만드는 건 쉽고, 관제와 안정화가 어렵다.
- **속도가 중요하다.** 1~2주 시험 사용 같은 선택지는 없다.
- **비슷한 통합 도구는 없고 전부 조각이다.** Agent of Empires, CloudCLI, Omnara, Superset, skillcp 등을 조사했다.
- **최종 목표**: 모바일에서 내 Mac과 여러 서버를 한 번에 지휘한다.

## 2. 대체하지 않는 것

- **Ghostty, Herdr**: 작업 공간이라 새 터미널 앱은 만들지 않는다.
- **brgr**: 잘 만들어진 위임 계약이라 그대로 쓴다.
- **각 하네스**: 실제로 일하는 주체다.
- **Tailscale**: 머신을 연결하는 전제다. 안 쓰면 WireGuard가 들어간다. 다만 교체할 수 있게 둔다.

## 3. 버린 선택지와 이유

## 4. 제약 (반드시 지킨다)

- **Claude ToS**: Claude 구독은 Claude Code 안에서만 쓴다. GJC 등 서드파티 하네스에서 Claude 모델을 쓰지 않는다. ✅ `lib/gjc`가 anthropic, claude, opus, sonnet, haiku, fable 이름이 든 모델을 거부한다.
- **head는 코드를 만지지 않는다.** ✅ GJC를 `--no-mcp`에 도구 없이 실행하고, 도구 실행이 감지되면 그 실행을 중단한다.
- **AGPL 격리**: gajae-way 코드를 섞지 않는다.
- **커널이 유일한 통로다.** ✅ 플러그인끼리 직접 통신하지 않는다.
- **localhost 전용** ✅ (자세한 내용은 11절)

## 6. 아키텍처

### 6.1 전체 구조
- **커널 + 플러그인 구조다.** 모든 기능이 플러그인이다. ✅
- 커널에 남는 것은 6가지다. ✅
  - 실행기: 띄우기, 감시, 재시작, 격리
  - 중계
  - 저널
  - 상태(일반 엔티티)
  - 권한과 승인 관문
  - 프로토콜
- 플러그인을 띄우는 기본 실행기만은 플러그인이 될 수 없다.
- 커널이 하지 않는 것: 화면, AI 호출, 하네스에 대한 지식, 위임 판단, 사용자 인증 방식, 비밀 값 저장(경로만 넘긴다).
- 커널의 범위를 정하는 기준: **플러그인에 맡기면 플러그인끼리 서로를 망가뜨리거나 우회할 수 있는 것만 커널이 한다.**

### 6.2 헥사고날
- **바깥 헥사고날은 이미 갖춰져 있다.** 플러그인 프로토콜이 포트이고, 커널이 코어이고, 플러그인이 어댑터다.
- 🟡 **안쪽 헥사고날은 도메인 로직이 큰 플러그인에만 적용한다.**
  - gjc-head: `domain/`(라우팅 규칙), `ports/`(Brain, Judge, Delegator, Store), `adapters/`
  - brgr 플러그인: 작업 상태 전이와 CLI 호출을 분리
- 커널, slang, summarize, jev는 나누지 않는다.

### 6.3 기술 스택
- 런타임: Bun (커널, 웹) ✅
- 저장소: SQLite 파일 하나 (저널 + 엔티티) ✅
- 웹: React + Bun 내장 번들러. Vite는 쓰지 않는다. ✅
- 플러그인 언어는 자유다. 🟡 Go, Rust, TS, Python 지원 (8절)

## 7. 플러그인 프로토콜 v1 ✅

- **전송**: JSON-RPC 2.0, 한 줄에 프레임 하나(NDJSON).
  - 지금은 stdio를 쓴다.
  - 나중에 Unix 소켓을 쓴다. 바뀌는 건 전송뿐이다.
- **매니페스트(`plugin.json`)**: 정적 파일이다. 실행 전에 권한을 확정하고, 핸드셰이크에서 권한을 늘릴 수 없다.
- **호출**: 다른 플러그인은 `invoke(대상, 메서드)`로 부른다. 매니페스트의 `provides.methods`에 있는 것만 부를 수 있다. 커널 자신의 메서드는 직접 호출한다.
- **스트리밍**: 호출하면 `opId`를 바로 받고, 진행 상황은 `op.update`, 끝은 `op.end`로 온다. `op.subscribe`와 `op.cancel`도 있다.
- **이벤트**: `<플러그인 id>.이름` 이름공간을 쓴다. 저널에 남긴 **뒤에만** 전달한다.
- **엔티티**: 종류별 JSON 문서다.
  - 쓰기는 종류의 소유자만 할 수 있다. 다른 플러그인은 `write-state`와 소유자의 `allowWriters`가 둘 다 있어야 한다.
  - 최소한의 스키마 검사를 한다.
  - 커널 자신의 상태도 `kernel.plugin` 엔티티로 노출한다.
- **권한**: `read-state`, `write-state:<kind>`, `emit`, `subscribe`, `call:<id>`, `call:*`, `approve.request`, `approve.decide`, `journal.read`, `shell`, `network`
  - `shell`과 `network`는 선언용이다. 커널이 막지는 못한다.
- **승인 관문**: 결정은 커널을 거친다. 요청한 플러그인이 스스로 결정할 수 없다. 만료되면 거절로 처리한다. `approval.list`도 있다.
- **추적**: 모든 프레임에 `seq`, `traceId`, `causationId`가 붙는다. SDK가 자동으로 이어 준다.
- **오류 코드**: -32001 ~ -32006
- **실행 방식 C**: Mac 안의 플러그인은 커널이 띄우고, 원격 데몬은 스스로 접속한다. ✅ 지금은 커널이 띄우는 방식만 있다.
- **MCP 어댑터**: MCP 서버를 플러그인으로 감싼다. 🟡

## 8. 다언어 지원과 호환성 🟡

- **규격 원본을 언어 중립 스키마로 옮긴다.** 지금 원본인 `types.ts`를 JSON Schema 같은 형식으로 바꾸고, TS·Go·Rust·Python 타입은 거기서 생성한다.
- **적합성 테스트**: 어떤 언어의 플러그인이든 이걸 통과하면 호환된다고 본다.
- **SDK는 얇게**: 연결, 호출, 스트리밍, 추적 전달만 담는다. 실제로 그 언어로 플러그인을 쓸 일이 생길 때 만든다.
- **범용 브리지**: 설정만으로 바깥 것을 붙인다.
  - `mcp-bridge`, `cli-bridge`, `acp-bridge`, `http-bridge`
  - ✅ 네 개 모두 `bridges/`에 있다(`mcp`, `cli`, `http`, `acp`). `me adapt`가 자동으로 쓰는 것은 아직 `mcp`, `cli`뿐이다.
  - `http-bridge`: 호출자는 경로·쿼리·헤더·본문만 채우고 스킴·호스트·포트는 바꿀 수 없다. 비밀 헤더는 파일 경로로 받고, 리다이렉트는 따라가지 않으며, 응답 크기에 상한을 둔다.
  - `acp-bridge`: ACP 버전 1(`@agentclientprotocol/sdk` 1.3.0 스키마 기준)의 클라이언트다. 파일 시스템·터미널 기능은 제공하지 않고, 에이전트의 권한 요청은 설정 정책으로 자동 응답한다(기본 거절).
  - 하네스는 brgr로 붙인다.
- **`me adapt`**: 바깥 것을 한 번에 붙여 주는 도구다. 세 단계를 차례로 시도한다.
  1. **마켓플레이스**: 이미 누가 만든 어댑터가 있으면 그대로 받는다.
  2. **범용 브리지**: 맞는 브리지가 있으면 매니페스트만 생성한다. LLM을 쓰지 않아 비용이 없다.
  3. **에이전트 작성**: 둘 다 없을 때만 에이전트가 토큰을 써서 어댑터를 작성한다(brgr로 위임).
  - 어느 단계든 **적합성 테스트를 통과해야 활성화**한다. 적합성 테스트가 믿음의 근거다.
  - 대상이 업데이트돼서 테스트가 깨지면 다시 만든다.
  - 새로 만든 어댑터는 마켓플레이스로 돌아간다.
  - 진행 방식은 brgr `harness add`의 "점검 → 계약 테스트 → 시험 실행 → 활성화" 패턴을 따른다.
- 목표 저장소 구조: `spec/`, `kernel/`, `sdk/{ts,python,go,rust}`, `bridges/`, `plugins/`, `tools/adapt/`
- 순서
  1. 스펙 원본과 적합성 테스트
  2. head와 brgr를 헥사고날로 정리하며 9.4절의 1~4번 반영
  3. 브리지 하나(MCP)
  4. `me adapt`
  5. 나머지 언어 SDK

## 9. head와 판정 흐름

### 9.1 head
- **GJC가 head다.** ✅ json 모드로 실행한다(`-p --mode json --no-mcp`, 도구 없음).
- 모델: `openai-codex/gpt-5.6-luna` ✅
- 대화는 스레드마다 GJC 세션 ID로 `--resume`해서 이어 간다. 같은 cwd에서만 된다. ✅
- 코드 작업이 필요하면 무조건 위임하고, 간단함 확률이 0.8 이상일 때만 직접 답한다. 애매하면 위임한다. ✅
- Claude가 필요한 작업은 Claude Code에 위임한다. ✅

### 9.2 판정 흐름 ✅
1. **slang**: 사전으로 줄임말을 바꾼다. LLM은 쓰지 않는다.
   - 기본 사전: ㄱㄱ, ㅇㅇ, ㄴㄴ, ㄹㅇ, ㅇㅋ, ㄱㅊ, ㅈㅅ, ㅎㅇ, ㅁㄹ, 억까, 하셈, 존나, 개좋
   - 사용자 사전은 따로 추가할 수 있다.
2. **summarize**: LLM 한 번으로 영어 구조화 요약을 만든다. 요약, 지시서, 코드 필요 여부, 범위, 추천 하네스가 들어간다. 이 지시서가 위임 지시서로 그대로 쓰인다.
3. **jev**: 영어, 긍정형으로 고정한 질문으로 판정한다.
   - OpenRouter 키 파일이 있으면 `typesafe/jev-router`를 쓴다. 실제 API는 아직 검증하지 않았다.
   - 키가 없으면 head 모델로 같은 형식의 대체 판정을 한다.
4. 웹에 "이렇게 이해했어요"와 판정 배지를 보여 준다.

### 9.3 Jev
- TypeSafe AI가 만든 의사결정 모델이다. Choice, Score, Noul 모드가 있다.
- 한국어와 부정문에 약해서 질문을 영어로 고정했다.
- `opencode-zen/jev-1.13-free`는 OpenCode 밖에서 못 쓸 것으로 보인다.
- ✅ (2026-10-11 실측) **Jev 본체는 OpenRouter의 `/api/alpha/decisions` 엔드포인트로 쓴다.** 모델은 `~typesafe/jev-latest`(응답 기준 `typesafe/jev-1.13-20260917`)다.
  - 요청 형식: `{ model, state, questions: { simple: { type: "noul", instructions } } }`. 응답은 `answers.simple.noul`(참일 확률)이다.
  - 응답 시간은 0.4~0.6초, 1회 비용은 약 $0.00001이다.
  - `typesafe/jev-router`는 Jev 본체가 아니다. Jev가 고른 다른 LLM(gpt-6-luna, deepseek 등)으로 넘기는 채팅 라우터라서, 판정용으로 쓰면 2~8초가 걸린다. 처음 구현이 이것을 쓰고 있었다.

## 10. brgr 플러그인 ✅

- 소유자는 에이전트가 아닌 고정 이름이다(`me:mac`).
- **커널은 에이전트가 없는 Herdr pane에서 실행해야 한다.** 그래야 brgr가 워커 pane을 옆에 연다.
- 동작은 `run --capture-diff` → `wait` → `result` → `accept`/`reject`/`cancel`/`diff` 순서다.
- 작업은 `brgr.task` 엔티티로 저장하고, 상태가 바뀔 때마다 이벤트를 낸다.
- 대상 저장소에 커밋되지 않은 변경이 있으면 위임이 거부된다. 오류 메시지는 한국어로 보여 준다.
- 실제 Claude Code 위임으로 실행, 결과, diff, 수락, 거절을 모두 확인했다.
- 🟡 안쪽 헥사고날: `domain/`(상태 전이, 커밋 메시지, diff 파일 목록), `ports/`(BrgrCli, Git, TaskStore, Events), `adapters/`(brgr·git CLI, 커널 SDK), `app/`(유스케이스). `main.ts`는 배선만 한다.
- 🟡 수락 = 적용 + 커밋(9.4-2): sealed만 수락하고, 작업 트리(추적 파일)가 깨끗해야 `brgr accept` → `brgr apply --workspace <project> --execute` → diff가 건드린 파일만 스테이징해 커밋한다. 성공하면 `applied`(commitSha, appliedAt), 실패하면 `apply-failed`. 실제 brgr/git으로는 아직 확인하지 않았다.

    - 원본 읽기는 `source.get`(비밀 값은 `<set>`으로 가림), 원본 고치기는 `source.update`(공유 바꾸기·서버 빼기·필드로 추가/고치기; 비밀스러우면 0600 파일 참조로 저장), 초안 채택은 `draft.adopt`(충돌마다 쓸 쪽을 골라야 함; 파일이 바뀌면 지문 불일치로 거부), 적용은 `apply.request`(새 plan을 고정하고 승인 게이트를 거쳐 승인 때만 적용; ops 조치와 같은 방식)다. 원본 쓰기는 백업을 남긴다.
    - 서버를 원본에서 빼면 하네스 파일에서는 손대지 않고 관리 대상에서만 빠진다(다음 import가 사용자 것으로 취급). 파일에 남은 건 각 앱에서 지운다.

## 20. 세밀한 상태와 화면 재구성 (2026-10-11)

- **상태는 커널이 공통으로 추적한다.** 무엇을 하는지는 플러그인이 단계(phase)로 말하고, 지금 어떤 상태이고 얼마나 걸리는지는 커널이 기록한다.
  - `kernel.op` 엔티티: 진행 중, 승인 대기, 완료, 실패, 취소
  - `trace.get`: 요청 하나의 호출 트리
  - 플러그인 건강 정보: `activeOps`, `lastError`
  - 자세한 내용은 PROTOCOL 15절에 있다.
- **head는 단계를 보고한다**: 이해 → 판정 → 답변 작성 / 지시서 작성 → 승인 대기 → 위임 → 완료.
- **스트리밍 체감 개선**
  - 메시지가 오면 GJC를 미리 띄워서, 프로세스 시작이 판정 시간 뒤로 숨는다.
  - 직접 답변은 생각 단계를 끈다(기본 설정에서 첫 글자까지 시간이 최대 6초로 튀었다).
  - 첫 글자까지 남은 2~2.5초는 모델 제공사의 응답 시간이다.
  - 실측: 단계 표시는 0.1초부터, 첫 글자는 3.0초(이전 3.9초)에 나오고, 이후 글자가 이어서 흘러나온다.
- **화면을 Orca식으로 재구성했다.** (조사: `stablyai/orca`)
  - 데스크톱은 왼쪽 레일, 폰은 하단 탭이다. 탭은 대화 / 작업 / 승인 / 운영 / 프로젝트다.
  - 해시 라우팅을 쓴다.
  - 대화에서 위임은 한 줄 요약으로 접고, 판정 칩을 누르면 타임라인 드로어가 열린다. "문제 신고"는 그 드로어 안에 있다.
  - 작업 화면은 확인 필요, 진행 중, 완료, 실패로 묶는다. 상세의 리뷰 화면 하단에 "수락(적용+커밋)" 바가 고정된다.
  - 상태는 점 하나와 글자 라벨로 표시한다. 색은 상태에만 쓴다.
- **사고 기록**: UI 워커가 `pkill -f`로 사용자의 me까지 종료했다. 바로 다시 띄웠고, 서버는 15초 만에 스스로 다시 붙었다. 원칙은 "자기가 띄운 PID만 종료한다"이다.

## 21. 저널 쓰기 줄이기 (2026-10-11, #3 #4)

- **기준선**(사용자 `~/.me`): events 2117행 / 515KB, 대부분 60초마다 바뀌지 않은 ops 점검 upsert. op.update 1006행 중 text_delta 939행. SQLite 1.1MB + WAL 2MB, 보존 정책 없음.

  - 저장된 `checkedAt`은 최대 10분(+점검 주기) 늦을 수 있다. 최신 값은 `checks.list`가 준다.

## 22. ops 조치: 승인 뒤에만 실행한다 (2026-10-12, #16)

- **점검마다 조치를 설정에 적는다.** `actions: [{ id, label, kind, ... }]`. 종류는 `systemd-user-restart`(`unit`), `launchd-restart`(`job`), `command`(`argv`) 세 가지다.
  - 실행할 argv는 설정을 읽을 때 정해진다. 화면이나 호출이 보내는 것은 점검 id와 조치 id뿐이고, 사용자 글은 argv에 들어가지 않는다. 승인할 때의 `amend`도 무시한다.
  - 서비스 이름은 `-`로 시작하거나 공백, `/`가 있으면 거부한다. 잘못된 조치가 하나라도 있으면 그 점검 전체를 오류로 돌린다.
- **실행은 언제나 커널 승인 관문을 거친다.** `actions.run {checkId, actionId}`은 바로 `waiting`을 돌려주고, 승인을 요청한다.
  - 위험도는 `medium` 이상이다. 설정의 `low`는 `medium`으로 올린다.
  - 요약에는 어느 기기(호스트 이름과 ops id)에서 무엇을(argv 그대로) 실행하는지 적는다.
  - 승인하면 시간 제한(기본 30초, 최대 10분) 안에 셸 없이 실행하고 출력 끝 2,000자를 남긴다. 3초 뒤 점검을 다시 돌린다. 거절이나 만료(10분)면 아무것도 실행하지 않는다.
  - 결과는 점검 레코드의 `lastAction`에 남는다. 다시 돌린 점검은 관측 하나로만 기록하고, 상태 확정은 평소처럼 `confirm` 규칙을 따른다.
  - 한 점검에는 한 번에 조치 하나만 진행한다. ops가 다시 시작되면 끝나지 않은 조치는 실패로 닫는다.
- **원격 ops도 같은 코드다.** 서버의 `me connect`로 붙은 `ops-<이름>`도 같은 메서드를 갖는다.
  - 원격 인스턴스가 승인을 요청하려면 Mac 커널의 `remotePermissions`에 `approve.request`가 있어야 한다. 없으면 조치는 실행 전에 실패로 기록된다. 이 설정은 사용자가 직접 바꾼다.
  - 서버의 코드 사본도 다시 보내야 새 메서드가 생긴다.
- **웹의 호출 권한을 `call:*`로 바꿨다.** ops 인스턴스 이름(`ops-rapi` 등)은 기기마다 정해지는데, 커널의 권한에는 접두사 와일드카드가 없다.
  - 버린 대안: 커널에 `call:ops-*` 같은 접두사 권한 추가(프로토콜 변경), 매니페스트에 인스턴스 이름 나열(사용자 기기 이름이 커밋됨).
  - 웹 서버는 요청마다 대상을 고정한다. 조치 경로는 대상이 `ops` 또는 `ops-*`일 때만 호출한다.
- **화면**: 상태 탭의 문제 카드에 조치 버튼이 붙는다. 누르면 승인 카드가 작업 탭의 승인 요청에 뜬다. 카드는 실행할 명령(접힘)과 마지막 조치 결과를 보여 준다. 조치로 정상이 된 점검도 10분 동안 카드로 남아 결과를 보여 준다.

## 23. 대화별 접근 모드: 읽기만 / 프로젝트 쓰기 / 전부 알아서 (2026-10-12)

- **모드는 대화마다 하나다.** 값은 `read`(읽기만) · `project`(프로젝트 쓰기, 기본값) · `full`(전부 알아서)이다. 기본값은 `gjc-head.settings`의 `access`, 대화별 값은 `gjc-head.thread`의 `access`에 둔다. 대화는 자기 모드를 유지하고, 새 대화는 기본값을 물려받는다. `chat.settings.set`과 `chat.thread.set`이 `access`를 받고, `full`로 바꿀 때는 `confirm: true`가 있어야 한다. `chat.send`의 `access`는 새 대화에만 쓴다.
- **위임이 모드를 따른다.** `read`에서는 위임하지 않고, 위임 판정이 나면 "읽기 전용이라 위임하지 않았다"는 짧은 답과 입력창 옆 모드 안내로 대신한다. `project`와 `full`에서는 커널 승인 없이 바로 위임하고, 승인 기록은 메시지의 `delegation.approvedBy`(`mode:project` | `mode:full` | `user`)와 turn update에 남긴다. 자동 모드에서는 요약이 권하는 하네스와 하네스 기본 작업 설정을 쓰고, `amend` 경로는 승인이 있을 때만 그대로 둔다.
- **자동 적용은 `full`에서만 한다.** gjc-head가 `task.delegate`에 `autoApply: true`를 싣고, brgr는 봉인된 성공 결과(`candidate`)를 수동 수락과 같은 accept→apply→commit 경로로 바로 적용한다. 실패 결과는 절대 자동 적용하지 않고, 적용 실패는 `apply-failed`에 에러와 함께 남긴다. 저장소가 더러우면 기존 검사가 그대로 막고 봉인 상태로 둔다.
- **웹은 값만 넘긴다.** `head.defaults.set`, `head.thread.set`, `chat.send`가 `access`/`confirm`을 그대로 전달하고, 화면은 다른 워커가 고친다. bootstrap은 기존 `headSettings`와 스레드 엔티티로 모드를 노출한다.
- **E2E도 계약에 맞췄다.** 승인 대기 흐름 대신 자동 위임 → 수락 → 커밋, 읽기 전용 안내, `full`의 confirm·`autoApply` 전달을 확인한다.

## 24. 무인 위임 예산: budget 플러그인 (2026-10-12)

- **토큰을 세는 대신 두 가지를 본다.** 작업별 토큰 집계가 없어서, 예산은 (a) 로컬 `meter status --json`의 제공자별 남은 양과 (b) brgr 작업 이벤트로 센 위임 횟수다. `budget.check`는 brgr가 매 위임 전에 부르고, `budget.status`는 설정 일반란에 한 줄로 보인다.

- **기준은 부드럽게 두 단계다.** 남은 양이 `minRemainingPercent`(기본 10) 밑이면 승인 요청, `hardStopPercent`(기본 3) 밑이면 중단. 하루 횟수(기본 30건, 자동 적용 10건)는 넘으면 바로 막는다.
- **버린 대안**: 커널에 예산 검사 내장(도메인을 아는 커널이 된다), 위임 횟수를 메모리에만 두기(재시작하면 리셋된다), meter 실패 시 위임 중단(오프라인에서 me가 멈춘다).

## 26. brgr 검사 게이트, 동시성 큐, 예산 훅 (2026-10-12)

- **검사 게이트**: 봉인된 후보 diff는 수락 전에 프로젝트 검사를 먼저 돌린다. 명령은 `pluginConfig brgr.verify`의 프로젝트별 지정이 우선이고, 없으면 worktree의 `package.json` 스크립트(`typecheck` → `lint` → `test` 순, lockfile로 구분한 패키지 매니저로 실행)를 쓴다. 없으면 "검사 없음"이다. 검사는 프로젝트를 깨끗하게 복제한 임시 디렉토리에 diff를 적용하고 돌리며, 명령마다 10분 제한(설정 가능)과 출력 끝 4,000자만 task 엔티티의 `verify`에 남기고 `brgr.task.verified`를 낸다. 자동 적용은 통과(또는 검사 없음 + `verifyRequired: false`)일 때만 진행하고, 실패하면 한국어로 이유를 남기고 사용자 수락을 기다린다. 수동 수락은 검사 결과와 무관하게 항상 된다.
- **동시성 큐**: 프로젝트당 실행 중 위임은 하나, 전체는 `maxRunning`(기본 3)개까지다. 넘치는 위임은 `queued` 상태의 task 엔티티로 저장돼서 커널 재시작 후에도 순서대로 다시 시작하고, 자리가 나면 FIFO로(막힌 앞 순서가 뒤 프로젝트를 막지 않게 건너뛰며) 시작한다. 큐에 있는 동안의 brgr id는 `remoteId`에 따로 두고, 화면에는 "대기 중 · 앞에 N개"로 보인다.
- **예산 훅**: 위임을 시작하기 전(꺼낼 때도 다시)에 `budget` 플러그인이 있으면 커널을 거쳐 `budget.check`을 부른다. 거부는 한국어로 위임을 막고, 승인 요청은 예전 ask 방식과 같은 커널 승인 관문을 거쳐 결정될 때만 시작한다. 플러그인이 없거나 호출이 실패하면 한 번만 기록하고 그대로 진행한다. 권한에 `call:budget`과 `approve.request`를 선언했다.
- **버린 대안**: 큐를 메모리 FIFO만으로 두기(재시작하면 대기 순서가 날아간다), 검사를 사용자 프로젝트에서 바로 돌리기(검사 자체가 트리를 건드릴 수 있다).

## 27. brgr 검사 게이트: 작업 worktree 우선, 의존성 설치, 자식 환경 (2026-10-12)
- **검사는 작업의 brgr worktree가 살아 있으면 거기서 바로 돌린다.** 워커의 결과가 이미 들어 있고 의존성도 보통 깔려 있어서, 임시 복제보다 빠르고 거짓 실패가 없다. 검증자는 추적 파일을 직접 고치지 않고(껍데기 diff도 적용하지 않는다), 검사 명령이 쓰는 파일은 worktree가 일회용이라 괜찮다. worktree가 없으면 예전처럼 임시 복제로 돌아가고, 이때는 상태가 알려 준 기준 커밋에 맞춘 뒤 diff를 적용한다. 기준을 모르면 HEAD다.

- **검사 전에 의존성이 비었으면 한 번 깔고 시작한다.** `package.json`과 lockfile이 있는데 `node_modules`가 없으면 매니저에 맞는 고정 설치(`bun install --frozen-lockfile`, `pnpm install --frozen-lockfile`, `npm ci`, `yarn install --immutable`)를 같은 제한 시간 안에 한 번 돌리고, task의 `verify`에 "의존성 설치" 항목으로 남긴다. 설치가 깨지면 검사 실패가 아니라 실행 오류로 다루고 한국어 이유를 남긴다.
- **검사 자식은 `childEnv`만 받는다.** `execWithTimeout`이 기본으로 allowlist 환경만 물려주고, brgr 매니페스트의 `run.envPass`가 있으면 그것만 더한다. 매니페스트는 커널이 보내 주지 않아서 플러그인이 자기 `plugin.json`을 직접 읽는다(`pluginConfig`에 중복 선언하지 않는다).
- **껍데기는 그대로 셸, 감지는 셸 없이.** 설정의 자유 명령은 인자·파이프·환경 대입이 올 수 있어서 `sh -c`로 돌리고(주석에 이유를 적었다), 감지한 `매니저 run 스크립트`는 고정 단어라 바로 실행한다. 출력은 예전처럼 끝 4,000자만 남긴다.

## 28. 대화 head 모델 fallback (2026-10-12)
- **설정**: `gjc-head` 설정에 `fallbackModels: string[]`(순서대로 시도, 비어 있으면 오늘처럼 실패)와 `cooldownSec`(기본 600)를 뒀다. Anthropic 이름이 든 fallback은 다른 head 선택과 같은 문구로 거부한다(ToS).
- **분류는 순수 함수다.** `plugins/gjc-head/src/domain/fallback.ts`의 `fallbackReason`이 quota·인증 만료·모델 없음·제공자 5xx/네트워크면 이유를 돌리고, 컨텍스트 초과·거부·도구 가드 위반·사용자 취소면 null을 돌린다(겹치면 후자가 이긴다). `describeFailure`는 이 분류를 그대로 물어봐서 새 원인 `model-unavailable`(기본 모델을 쓸 수 없어요)을 기록한다. 로그인이 원인일 때는 기존 `gjc-login`이 먼저 잡는다.
- **같은 턴 안에서 모델마다 한 번씩만 다시 한다.** 직접 답변(`answerDirectly`)이 대상 실패를 만나면 순서대로 다음 모델로 같은 프롬프트를 보내고, 실패한 모델은 쿨다운에 넣고 쿨다운 중인 모델은 건너뛴다. 전부 깨지면 오늘처럼 메시지가 실패한다. 쿨다운이 지나면 다음 턴에서 기본 모델을 먼저 쓴다. 성공하면 메시지에 `fallback: {from, to, reason}`을 남기고 `kind: "fallback"` turn update(저널에 남는다)를 보내며, 기본 모델의 alert는 지우지 않고 남겨서 고치게 한다.
- **판정·지시서 호출은 손대지 않았다.** jev는 OpenRouter→GJC 자체 chain이 있어서 그대로 두고, summarize의 모델은 그 플러그인이 소유해서 head에서 바꿀 수 없다. 순서만 공유하려고 재시도 뼈대(`lib/gjc`의 `withModelFallback`, 도메인 이름 모름)는 공용으로 뺐다.
- **버린 대안**: 커널에 fallback 내장(도메인을 아는 커널이 된다), summarize 호출을 같은 파라미터로 맹목 재시도(다른 모델이 아니라서 quota 외에는 낫지 않는다), 실패한 시도의 부분 스트림을 화면에서 되돌리기(이미 보낸 update는 되돌릴 수 없어서 최종 텍스트만 정확히 저장한다).

## 29. 휴대폰 푸시 알림: 웹 플러그인의 VAPID 푸시 (2026-10-12)
- **VAPID 키는 플러그인 데이터 dir에 한 번만 만든다.** `push-vapid.json`에 0600으로 두고 계속 쓴다. 공개 키만 `push.publicKey`로 나가고, 개인 키는 로그에도 클라이언트에도 절대 안 나간다. 라이브러리는 잘 알려진 `web-push`(고정 3.6.7)를 쓰고, 직접 암호를 짜지 않는다.
- **구독은 저널에 안 남긴다.** endpoint·키는 비밀로 보고 데이터 dir의 `push-subscriptions.json`(0600)에만 둔다. 엔티티로 두면 커널 저널에 남아서, 푸시 벤더 주소와 키가 기록에 박힌다. 보낼 때 상태를 뺀 실패 횟수만 남기고, endpoint·키는 오류 로그에도 안 찍는다.
- **보내는 건 네 가지뿐이다.** 새 승인 대기("승인이 필요해요" + 요약), brgr 봉인·검증("작업 결과가 왔어요" + 작업 첫 줄), 작업 실패, 점검 down("점검이 실패했어요 · 이름"). 본문은 짧게 자른 한 줄에 비밀 마스킹을 먼저 하고, URL은 `#/chat/<대화>` 아니면 `#/settings/device`만 싣는다.
- **이벤트로 듣고, 폭주는 30초에 한 번으로 묶는다.** 승인은 `kernel.approval.pending`, 결과·실패는 `brgr.task.sealed/verified/failed` 이벤트로 바로 받고, 점검 down은 `kernel.entity.changed`에서 이전 상태를 기억해 바뀌는 순간에만 보낸다(처음 본 상태는 기준선이라 안 보낸다). 종류별로 30초에 한 번만 나간다. 404/410이 돌아온 구독은 지운다.
- **화면은 설정 일반란 한 줄만 건든다.** "이 기기에서 알림 받기" → 권한 → 구독 → `push.subscribe`, 구독 중에는 "이 기기에서 받는 중"과 "시험 알림"·"끄기"만 보인다. 못 쓰는 브라우저와 http 페이지에는 한 줄로 이유만 적는다. 전체 화면 뜯어고치기는 나중 일이다.
- **푸시는 브라우저 벤더 푸시 서비스로 나가는 게 웹 플러그인의 유일한 바깥 통신이다.** 보안 컨텍스트(https인 tailscale serve나 이 Mac의 localhost)에서만 된다.
- **버린 대안**: 구독을 엔티티에 두기(저널에 비밀 성격의 값이 남는다), VAPID 직접 구현(감사되지 않은 암호 코드가 늘어난다), 종류가 아니라 기기별로 묶기(같은 폭주가 기기마다 여러 번 나간다).

## 30. 예약 실행 schedule 플러그인과 메신저 notify (2026-10-12)
- **job은 두 곳에서 온다.** `pluginConfig schedule.jobs`(읽기 전용, id 유지)와 `schedule.add/update/remove`로 만든 실행 기록(`schedule.job` 엔티티)이다. 설정 job은 바꾸는 메서드가 거절하고 `runNow`만 받는다. 삭제는 커널에 지우기가 없어서 tombstone으로 남기고 목록에서 숨긴다.
- **시각은 지역 시간대 벽시계로 본다.** 다음 시각 계산은 Intl 벽시계 달력으로 하고, cron은 분 단위로 벽시계를 돌려서 찾는다. 봄 DST 빈 시각(02:30)은 다음 유효한 날로 미루고, 가을 겹치는 시각은 첫 번째를 쓴다. dom·dow는 cron답게 한쪽이 `*`이면 다른 쪽만 보고, 둘 다 있으면 둘 중 하나라도 맞으면 된다.
- **켜져 있지 않을 때는 놓친 만큼만 남긴다.** 매 틱 끝마다 `schedule.state`에 살아 있음 표시를 남기고, 시작할 때 그 뒤의 예약 시각을 다시 세어 60초가 지났으면 `missed`로 한 번만 남기고(실행 안 함), 60초 안이면 바로 실행한다. 실행 기록의 `at`은 예약 시각 그대로 두어서, 답이 늦게 와도 놓친 기록이 두 번 남지 않는다.
- **실행은 겹치지 않는다.** 같은 job이 돌고 있을 때 때가 되면 `skipped`으로 남긴다. 시작이 실패하면 최대 두 번 기다렸다가 다시 시도하고, 그래도 안 되면 `failed`로 남긴다. 답이 다 되면(`gjc-head.message.changed`) 앞 600자를 `lib/redact`로 가려서 `deliver`에 적힌 메신저로 보낸다.
- **쓰기는 승인 없이 나가지 않는다.** `project`·`full` 접근은 실행 때마다 커널 승인을 물어보고, 거절되면 실행하지 않는다. `allowUnattendedWrite: true`일 때만 묻지 않는다.
- **메신저 쪽은 한 줄짜리 `notify`다.** `discord.notify`·`slack.notify {text}`는 설정의 `notifyChannel`에 답장과 같은 원장으로 올린다(비밀 가림, 중복 표시 그대로). 메신저 플러그인이 없으면 한 번만 알리고 웹 결과만 남긴다. schedule은 `me.config.json`에 기본 등록하되 job 없이 두어서, 아무 설정 없이도 me가 그대로 돈다.
- **버린 대안**: head 스레드 제목을 schedule이 미리 쓰기(커널이 다른 플러그인 엔티티 쓰기를 막아서 head 기본 제목을 그대로 쓴다), 삭제용 엔티티 지우기 새로 만들기(커널을 건드릴 일이라 tombstone으로 둔다), 예산 검사 직접 호출(brgr가 위임 전에 이미 하므로 예약 실행은 head에 맡긴다).

## 31. brgr 작업 준비(신뢰·파일·설치)와 되돌리기 (2026-10-12)
- **신뢰는 Codex만 미리 심는다.** Codex 일회성 실행은 이미 샌드박스 우회 인자를 달고 나가서 묻지 않지만, 대화형 워커 TUI(빈 `codex`)는 새 worktree에서 폴더 신뢰에 걸릴 수 있다. 위임 전에 `~/.codex/config.toml`의 관리 블록에 brgr worktree 루트만 신뢰로 적고(그 바깥은 절대 안 건드린다), 사라진 worktree 항목은 값이 쌀 때 치운다. 블록 밖에 이미 있는 `[projects."경로"]`(Codex가 신뢰 프롬프트 수락 때 직접 적는다, 작은따옴표·여백 변형 포함)는 블록에서 빼서 표가 두 번 적히는 일을 막고, 못 믿음으로 둔 바깥 항목은 그대로 두며, 앞뒤 TOML이 깨지면 쓰지 않고 파일 권한은 그대로 둔다. Claude의 `~/.claude.json`은 실행 중인 세션들이 수시로 다시 써서 원자적 읽기-수정-쓰기가 불가능하다(덮어쓰면 남의 기록을 지운다). 그래서 손대지 않고, 일회성 실행의 `-- permission-mode bypassPermissions`에 기대고 남음은 brgr 하네스 쪽에 맡긴다고 보고서에 적었다.
- **파일은 `.worktreeinclude`와 설정으로 실어 보낸다.** 프로젝트의 `.worktreeinclude`(gitignore식: 빈 줄·`#` 무시, `/` 없는 이름은 모든 깊이, 끝 `/`는 폴더 통째, `!`는 제외)와 `pluginConfig brgr.include`를 모아 `brgr run --snapshot-path`로 반복 전달해서 워커 밑바탕에 깐다. 비밀 파일(.env류)도 로컬 한정으로 허용하되 이름·내용을 어디에도 기록하지 않는다. 합계 5MB가 넘으면 통째로 빼고 작업에 한국어 경고를 남긴다. 목록 뽑을 때 `.git`·`node_modules`는 건너뛰고(글자 그대로 적은 경로는 그대로 찾는다), 심볼릭 링크는 프로젝트를 벗어날 수 있어 뺀다.
- **설치 명령은 지시문 한 줄로 보낸다.** `brgr run`에 설치 갈고리가 없어서 `pluginConfig brgr.setup`의 프로젝트별 명령을 objective 끝에 "Before starting, run: …" 줄로 붙인다. 한계는 문서와 코드 주석에 적었다.
- **되돌리기는 `task.revert` 하나로 한다.** 적용된 작업만 `git revert --no-edit`으로 되돌리고 `revert {commit, at}`를 남기며 상태는 `reverted`, 이벤트는 `brgr.task.reverted`다. 트리가 더러우면, 커밋이 지금 브랜치에 없으면, 합치기 커밋이면 한국어로 거절하고, 충돌하면 abort하고 트리를 그대로 둔다. 뒤 커밋이 같은 파일을 건드렸을 때만 커널 승인을 거치고, 아니면 바로 실행한다. 화면은 작업 패널과 대화 결과 카드에 같은 "되돌리기" 확인 버튼을 두고, 끝나면 "되돌렸어요 · 커밋 abcd1234"를 보여 준다.
- **버린 대안**: `~/.claude.json` 직접 수정(동시 기록자와 경합한다), 스냅샷을 임시 폴더에 복사해서 전달(절대 경로면 brgr가 프로젝트 기준으로 맞출 수 없다), 되돌리기를 항상 승인 관문으로(겹친 게 없으면 묻지 않는 게 빠르다).

## 32. 릴리스는 기본 패치로 올린다 (2026-10-13)
- **`me release`는 깃발 없이 패치를 올린다.** `--minor`를 줄 때만 마이너를 올리고, `--patch`는 그대로 두어도 된다(기본값과 같아서 아무 일도 안 한다). 마이너 올리기가 너무 잦았기 때문이다.

## 33. 대화 head 하네스 선택: GJC 그대로, OMP 추가 (2026-10-13)
- **플러그인 id는 `gjc-head` 그대로, 속만 고른다.** 설정·저널·화면이 id에 묶여 있어서 이름을 바꾸면 다 깨진다. 설정에 `harness: "gjc" | "omp"`(기본 `"gjc"`)와 하네스별 기본 모델 `models: {gjc, omp}`를 뒀다. 옛 `model`은 gjc 기본값으로 그대로 읽힌다.
- **실행 추상은 `lib/runner`에 한 곳에만 둔다.** GJC 코드는 `@me/gjc`에서 `@me/runner`로 옮기고 `@me/gjc`는 같은 이름 재보내기로 남겼다. OMP는 GJC와 깃발 모양이 같아서(`-p --mode json --tools/--no-tools --thinking --model`) 이벤트 읽기 코드를 공유한다. OMP에 `--no-mcp`는 없고, `--no-extensions` + `--no-skills` + 명시한 `--tools` 목록이 그 자리를 대신한다(도움말에 없음 확인). 세션은 `sessions-omp`에 따로 둬서 GJC 세션과 섞이지 않는다.
- **OMP 실측(2026-10-13, `omp` v18.2.7).** `say ok` 한 번이 `session → message_update(text_delta) → message_end → turn_end → agent_end`를 돌려주고, 도구 켜면 `tool_execution_start/end`도 GJC와 같은 이름으로 온다. 그래서 노출 도구 감시는 손대지 않았다. `omp models --json`으로 목록을 읽고 Anthropic 이름은 GJC와 같이 뺀다(ToS). `deepseek-v4.1-flash`는 구독이 없어 403이 났고, 기본 모델(`openai-codex/gpt-5.6-luna`)은 답·이어받기(`--resume`)·미리 띄우기(stdin 대기)까지 확인했다. 실측 한 줄 샘플은 `lib/runner/fixtures/omp-say-ok.jsonl`에 뒀다(서명 뭉치만 지움).
- **읽기 전용 규칙은 하네스와 상관없이 기계적으로 둔다.** 두 하네스 모두 도구 없이 띄우고, 허용 목록 밖의 도구 실행이 보이면 그 실행을 중단한다. Anthropic 검사는 모델 이름 앞의 `gjc:`·`omp:`를 떼고 본다.
- **fallback은 `harness:model`로 적는다.** 맨 모델 이름은 같은 하네스, `omp:모델`·`gjc:모델`은 그 하네스로 넘어간다. GJC 로그인 만료가 나면 OMP 차례로 넘어갈 수 있다. 같은 모델 이름은 하네스별로 따로 식힌다(`gjc:이름`, `omp:이름`).
- **알림은 하네스 이름을 밝힌다.** `omp-login` 원인을 새로 두고 "OMP 로그인이 만료됐어요 · 터미널에서 omp 실행 후 /login"을 보여 준다. GJC 문구는 그대로다.
- **summarize와 jev는 각자 `harness` 설정을 본다.** head 설정을 읽으러 오가면 느려지고 묶이니까, 세 곳에 같은 값을 적으면 따라온다. jev의 OpenRouter 먼저는 그대로다.
- **화면은 일반란 한 줄만 건든다.** "대화 엔진 실행 도구" 고르기와 한 줄 설명, 모델 고르기는 고른 하네스의 목록을 보여 준다. 전체 화면 손보기는 나중 일이다.
- **버린 대안**: 플러그인 id 바꾸기(설정·저널·화면이 다 깨진다), `lib/gjc` 안에 OMP 넣기(이름이 거짓말이 된다), summarize·jev가 head 설정을 매번 읽어오기(느리고 묶인다), 스레드마다 하네스 두기(모델 고르기와 기본값이 겹쳐서 헷갈린다).
- DESIGN 6·8절의 "head는 GJC" 서술은 전체 화면 손보기 때 함께 고친다.

## 34. 위임 커밋 제목은 summarize가 짓는다 (2026-10-13)
- **짧은 영문 제목(`commitSubject`)을 요약이 함께 만든다.** 기존엔 브리프 첫 줄을 72자로 잘라 제목으로 썼는데, 영어 지시문 첫 줄이라 단어 중간에 잘리고 뜻도 안 맞았다. 요약이 일의 제목을 60자 이내·마침표 없이 짓고, 코드에서 공백 정리·따옴표·마침표 제거·단어 경계 72자 상한으로 다듬는다. 일이 없으면 빈 문자열이다.
- **gjc-head가 위임 때 제목과 사용자 원문(`request`)을 함께 넘긴다.** brgr는 둘을 작업 엔티티에 저장한다. 커밋 제목은 제목 → 사용자 요청 첫 줄 → 브리프 첫 문장 순으로 쓰고, 절대 단어 중간에 자르지 않으며(공백 없으면 60자), 본문은 `Requested: <원문 앞 300자>` 다음 `Applied from brgr task <id> via me.`와 Co-Authored-By다. 되돌리기는 깃 기본 `Revert "<제목>"`을 그대로 둔다.
- **버린 대안**: 제목 도우미를 공유 라이브러리로 빼기(플러그인은 서로 가져오지 않아서 20줄을 두 곳에 둔다), 요청 원문 없이 브리프만으로 제목 짓기(사용자 말이 제목에 가장 가깝다).

## 35. brgr 워커 질문은 대화에서 답한다 (2026-10-13)
- **질문은 작업 상태에 둔다.** brgr가 `awaiting-input`을 감지하면 워커 메시지를 먼저 읽고 없을 때만 화면 상태를 짧게 가려 저장한다. 같은 질문에는 한 번만 답하고, 자유 답변은 `brgr message`, 선택지는 `brgr input`으로 보낸다.
- **답변 경로는 대화를 유지한다.** 웹 작업 카드·패널과 Discord·Slack의 기존 허용 사용자 대화에 질문을 보여 주고, 해당 대화의 답장을 작업에 연결한다. 메신저 전송은 기존 원장을 계속 쓴다.
- **버린 대안**: 새 승인/커널 메서드를 만들기(기존 brgr task 메서드와 messenger admission으로 처리 가능), 웹 Push에 별도 질문 종류를 추가하기(기존 카드와 대화 이벤트가 있어 별도 변경은 필요하지 않다).

## 36. 모호한 위임은 한 번 묻고 대화 스레드를 바로 연다 (2026-10-13)

- summarize의 기존 호출이 위임 요청의 중요한 모호함과 선택지를 함께 돌려준다. gjc-head는 읽기 전용·직접 답변에서는 묻지 않고, 기본 설정 `clarify: true`일 때 한 번 질문과 추천 선택지를 보여 준 뒤 다음 사용자 메시지를 요청에 합쳐 위임한다. 대기 상태는 스레드 엔티티에 저장해 재시작 뒤에도 이어진다.
- 웹의 `chat.send` 응답에 새 스레드 id를 포함해 첫 메시지 이벤트를 기다리지 않고 대화를 연다. 선택 제목은 새 스레드에만 적용하며, 예약 실행은 `⏱ <이름>`을 보낸다.
- `chat.thread.set`은 id를 확인한 다음에만 엔티티를 읽는다. 빈 입력이 커널 호출 프레임 오류로 이어지지 않게 한다.
- 버린 대안: 모호함 확인을 위해 모델을 한 번 더 호출하기(느리고 비용이 든다), 웹에서 첫 이벤트를 계속 기다리기(질문 대기 같은 빠른 응답에서 화면 전환이 늦어진다).

## 37. 지난 대화 검색과 프로젝트 기억: recall 플러그인 (2026-10-13)
- **검색은 recall 플러그인이 맡는다.** `gjc-head.message`와 Claude Code·Codex 대화 파일을 읽기 전용으로 훑어 SQLite FTS5에 넣는다. 비밀 마스킹을 거친 본문만 저장하고, 파일 변경 시 다시 읽으며, 인덱스 크기와 메시지 길이에 기본 상한을 둔다.
- **기억은 명시적으로 저장한다.** `recall.remember` 호출만 사실로 기록하고, `recall.context`는 프로젝트와 요청에 맞는 최근·고정 사실을 800자 안에서 반환한다. 자동 추출은 하지 않는다.
- **head는 위임 전에 프로젝트 기억을 조회한다.** `gjc-head`가 `recall.context {project, text}`를 호출하고, recall이 없거나 실패하면 빈 문맥으로 진행한다. 반환된 문맥은 800자 안에서 선택적인 요약 프롬프트 필드로 전달한다.
- **버린 대안**: 커널에 검색·기억 기능을 넣기(도메인 기능을 플러그인 밖으로 끌어온다), 대화에서 자동으로 기억을 만들기(사용자가 말하지 않은 사실을 저장하게 된다).

## 38. 에이전트 상태 피드와 멈춤 알림 (2026-10-13)
- **watch 플러그인은 Herdr 상태를 읽기만 한다.** 10초마다 pane 단위 상태를 저장하고, brgr 작업이 15분 동안 화면 변화가 없거나 최근 출력에서 같은 실패가 세 번 반복되면 `watch.stalled`를 낸다. 자동 취소 없이 설정의 기기 점검 화면에서 진행 상태를 보여 준다.
- **기기 점검은 다음 행동과 실제 그룹 수를 보여 준다.** 별도 안내가 없는 command 점검은 비밀을 가린 실제 argv를 터미널 명령으로 제안하고, 기기 수는 실패 수가 아니라 나열된 머신 그룹 수로 센다.
- **버린 대안**: 에이전트에 입력을 보내거나 멈춘 작업을 자동 취소하기(관제는 읽기 전용이어야 한다).

## 39. 회상 인덱싱과 위임 문맥 다듬기 (2026-10-13)
- **회상은 최신 파일부터 백그라운드에서 나눠 색인한다.** 예산은 원문 크기가 아니라 비밀을 가린 저장 본문 크기로 계산하고, 검색은 현재 색인만 읽는다. 명확화 답은 선택 문구를 지시서에 남기며, 위임 요약은 recall의 프로젝트 메모를 선택 입력으로 받는다.
- **버린 대안**: 검색 도중 전체 대화 파일을 동기적으로 읽기(검색 지연과 오래된 기록 우선 문제를 유지한다), 대화 원문 대신 선택 답만 작업 요청에 기록하기(사용자 표현을 잃는다).

## 40. 짧은 작업 요청도 판정하고 직접 답변을 위임으로 되돌린다 (2026-10-13)
- **fast path는 분명한 인사와 정보 질문에만 쓴다.** 작업 동사는 어미와 띄어쓰기를 흡수해 찾고, 짧아도 애매한 입력은 summarize/jev를 거친다.
- **직접 답변은 파일을 바꾸지 않으며 작업 요청에는 `[[DELEGATE]]`만 돌려준다.** head가 이 표식을 반환하면 같은 턴의 요약·위임 흐름으로 다시 보낸다. 읽기 전용 대화는 기존 안내를 유지한다.
- **이유**: 짧은 요청을 채팅으로 잘못 분류하거나, 도구 없는 head가 워커가 없다고 잘못 안내하는 일을 막는다.
- **버린 대안**: 사용자 프로젝트에서 바로 검사하기(검사 자체가 트리를 건드릴 수 있다), worktree가 없을 때 빈 상태로 검사를 돌리기(의존성 없는 JS 프로젝트는 매번 실패한다), 설치 실패를 검사 실패로 다루기(코드 문제가 아닌데 자동 적용을 막을 이유가 없다).
- **상태 파서는 중첩 모양을 읽는다.** `brgr status --json`의 실제 모양(`task.workspace`, `task.evidence.base_commit`, `workspace_present`, 앞의 안내 한 줄)에 맞췄다.

## 41. 릴리스 노트는 변경 근거에서 초안을 만든다 (2026-10-13)

- `me release`는 이전 태그 이후의 커밋 제목·본문과 결정 기록에 새로 더한 내용만으로 한국어 노트를 만든다. head 모델은 도구 없이 짧게 시도하고, 실패해도 커밋 제목을 담은 기본 노트로 릴리스를 계속한다.
- `me release notes --from <태그> [--to <태그|HEAD>]`는 같은 초안을 별도로 만들며 Git 기록을 바꾸지 않는다. `--dry-run`은 노트를 보여 주기만 하고, GitHub 릴리스 게시가 실패해도 이미 끝난 릴리스 절차를 실패로 바꾸지 않는다.
- `--joke`는 첫 문장만 가볍게 바꾼다. 나머지 설명은 제공된 근거만 쓴다.

## 42. 릴리스 노트 초안 제목과 문장 수를 정규화한다 (2026-10-13)
- 모델 초안에 제목이 빠지거나 같은 버전의 다른 제목이 오면 표준 `# me <버전>` 제목을 붙인다. 허용 목록 밖의 `##` 제목은 계속 거절한다.
- 문장 수는 문장부호가 실제 문장 끝에 놓였을 때만 센다. 버전, 파일 이름, `e.g.` 같은 약어의 점은 문장 끝으로 보지 않는다.
- 이유: 제목 형식 하나 때문에 유효한 한국어 노트가 버려지는 일을 줄이고, 초안 문장 수 제한을 정확히 적용한다.

## 43. 릴리스 노트의 농담과 범위 제목을 구체화한다 (2026-10-13)
- `--joke`는 가장 큰 변경에 연결된 짧은 실제 농담을 첫 문장으로 요청하고, 예시를 말투 참고로만 제공한다. 자료의 범위를 정확히 쓰고 모호한 세부 사항은 생략하도록 한다.
- `--from A --to B` 초안은 A 다음 첫 릴리스 태그부터 B까지를 제목에 표시하며, 초안 검증도 범위 제목을 허용한다.
- 이유: 농담이 따뜻한 요약으로 흐르는 것을 막고, 긴 범위 초안의 변경 구간과 기능 범위를 부풀리지 않게 한다.

## 44. 릴리스 노트는 영어와 한국어를 함께 제공한다 (2026-10-13)
- 한 노트에 영어를 먼저 쓰고 `---` 뒤에 한국어를 자연스럽게 다시 쓴다. 제목과 섹션은 언어별 허용 목록으로 검증한다.
- 모델이 없거나 초안이 형식에 맞지 않으면 영어에 커밋 제목을 나열하고 한국어에는 같은 목록을 가리키는 안내를 둔다. joke 모드는 각 언어에 맞는 농담을 따로 쓰며 영어 농담의 허용 표현을 제한한다.
- 이유: 릴리스 변경을 두 언어 사용자에게 한 파일에서 같은 근거로 전달하고, 농담과 대체 초안의 형식을 일관되게 유지한다.

## 45. 릴리스 노트 농담 기능 제거 (2026-10-13)
- 농담 품질이 낮아 기능을 뺐다. 노트는 근거에 충실한 영어·한국어 설명으로 작성한다.
