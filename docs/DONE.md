# 완료 기준 (Definition of Done)

모든 작업은 아래를 통과해야 끝난 것으로 본다. 통과하지 못한 항목이 있으면 보고서에 이유와 함께 적는다.

## 항상
1. **이슈**: GitHub 이슈 번호가 있다. 커밋 메시지에 `(#번호)`를 단다.
2. **정적 검사**: `bunx tsc --noEmit -p .`
3. **테스트**: `bun test`. 새 동작에는 새 테스트를 붙인다.
4. **적합성**: 플러그인을 바꿨으면 `bun spec/conformance/run.ts plugins/<id>`. 전체는 `bun bin/me.ts doctor`로 확인한다.
5. **E2E**: `bun run e2e`. 임시 me를 띄워 핵심 흐름을 실제로 돌린다.
   - 직접 답변: 단계 표시와 스트리밍
   - 위임: 판정 → 지시서 → 승인 → 결과 → 수락(적용+커밋)
   - 승인 거절
   - trace 타임라인
6. **문서**: 결정이 바뀌었으면 `docs/DECISIONS.md`, 프로토콜이 바뀌었으면 `docs/PROTOCOL.md`와 스키마를 고친다.

## 화면을 바꿨으면
7. **스크린샷**: `bun run shots`로 360·390·768·1280px × 라이트·다크를 찍어 직접 본다.
8. **접근성**: `bun run a11y`(axe) 위반 0건을 목표로 한다. 남은 위반은 이유를 적는다.
   - 키보드만으로 모든 화면을 쓸 수 있어야 한다.
   - 포커스 표시가 보여야 한다.
   - 상태 점에는 글자 라벨이 함께 있어야 한다.

## 성능을 바꿨으면
9. **수치**: 바꾸기 전과 후의 수치를 보고서에 적는다. 예: 번들 크기, 저널 행 수와 바이트, 첫 글자까지 걸린 시간

## 반영
10. **릴리스**: `bun run release`로 반영한다. 테스트, E2E, 태그, CHANGELOG, 실행 중인 me 재시작, 상태 확인, 원격 사본 갱신까지 한 번에 진행한다. 사용 중인 me에 손으로 반영하지 않는다.
