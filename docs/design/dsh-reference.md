# 레퍼런스: DeepSeek Harness (dsh)

DeepSeek Harness(dsh)의 UX와 구조를 정리하고, me에 무엇을 가져올지 적은 문서예요.

- **분석 대상:** `~/dev/_ref/deepseek-harness`, 커밋 `d7432673`(release 0.2.1-alpha.2), MIT 라이선스
- **확인 방법:**
  - 소스와 패키지 README를 읽었어요.
  - 공개 패키지 `@deepseek-ai/dsh@0.2.0-rc.2`를 임시 `DSH_HOME`, 포트 3090에서 띄워서 첫 화면과 접근성 트리를 확인했어요.
  - 모델 키 없이 띄워서 대화 턴, 승인, diff 화면은 소스와 테스트 기대값(`apps/web/tests/expected/`)으로 확인했어요.
- MIT 라이선스라 코드를 가져와도 되지만, 가져올 때는 출처와 라이선스 문구를 남겨요. gajae-way(AGPL)와는 다른 경우예요.

## 1. 한 줄 요약

dsh는 **대화 하나와 사이드바 하나**로 모든 걸 해요.

- **설정:** 모달 하나에 모여 있어요.
- **승인·질문·계획 검토:** 입력창 자리를 대신 차지하면서 떠요.
- **작업 세부:** 기본으로 숨기고, 원하는 사람만 "coding view"로 켜요.
- **구조:** 모든 기능이 플러그인이고, 세션 로그 하나가 유일한 진실이에요.

## 2. UX

### 2.1 화면 틀 (`packages/client/ui-layout`)

- **세 칸 구성:** 왼쪽 사이드바, 가운데 대화, 오른쪽 패널.
- **URL 라우터가 없어요.** 가운데는 대화 하나뿐이에요. Plugins와 Automation tasks만 사이드바의 "전역 패널"로 들어가고, 설정은 모달이에요.
- **사이드바:** 기본 280px이고, 접으면 56px 아이콘 줄만 남아요.
- **오른쪽 패널:** 기본으로 닫혀 있어요. 열면 화면의 45%를 차지하고, 탭으로 파일·브라우저·터미널·diff·하위 에이전트를 띄워요.
- **좁은 화면:** 1024px 아래에서 사이드바가 접혀요. 768px 아래에서는 오른쪽 패널이 전체 화면이 돼요. 모바일 전용 화면은 따로 없어요.

### 2.2 첫 실행

1. "Preview Notice" 창에서 [Continue]를 눌러요.
2. "Add an API key to get started" 화면에서 키를 넣어요. 버튼은 [Configure later]와 [Save and continue] 두 개예요. 한 화면에 한 단계만 보여 줘요.
3. 빈 설치면 **"Default workspace"와 빈 세션을 알아서 만들어서** 입력창을 바로 쓸 수 있어요.
4. 작업 공간이 없으면 입력창이 비활성 상태로 보이고 "Choose a workspace to start"라고 떠요. 입력창 카드를 누르면 폴더 선택기가 열려요.

### 2.3 사이드바 (`ui-sidebar`, `ui-workspace`)

- **위:** 로고, [New Session], 전역 패널(Plugins, Automation tasks).
- **가운데:**
  - "Workspaces" 아래에 작업 공간별 세션이 있어요. 세션은 5개까지 보여 주고 나머지는 "Show n more"로 접어요.
  - 실행 중인 세션은 접히지 않아요. 고정한 세션이 맨 위에 와요.
- **아래:** Settings와 연결 상태 표시.
- **세션 상태 표시:**
  - 실행 중이면 로더가 돌아요.
  - 끝났는데 안 본 세션에는 점이 찍혀요.
  - 대기 중이면 주황 점이 찍히고, **시간 자리에 "Approval", "Plan review", "Answer"가 대신 떠요.**
  - 그래서 확인할 게 있는 세션은 열어 보지 않아도 목록에서 바로 보여요.
- **줄 동작:** 고정, 이름 바꾸기, 포크, 보관.
  - 보관은 확인 없이 바로 되고, 토스트로 [Undo]를 줘요.
  - 실행 중인 세션을 보관하려 하면, 무엇이 멈추는지 목록으로 보여 주는 확인 창이 떠요.
- **보기 옵션:** 묶기(작업 공간, 경로 트리, 한 목록), 정렬(최근, 직접), 보관 필터.

### 2.4 빈 세션 화면과 입력창

- **빈 세션 화면은 위에서 아래로:**
  1. 제목 "Into the Unknown"
  2. [📁 작업 공간 ▾]와 [Standard mode ▾]가 한 줄에
  3. 입력창. 안내 문구는 "Describe what you want to build, / commands, @ files or sessions"
- **입력창 왼쪽:** `+`(파일, `/plan`, `/model`, `/permission` 등 명령 메뉴), 접근 모드, 계획 모드 칩(켜져 있을 때만 보여요).
- **입력창 오른쪽:** 모델과 effort 한 버튼("DeepSeek-V41-Flash High"), 보내기/멈추기.
- **필요할 때만 나타나는 것:**
  - 모델 검색: 모델이 4개를 넘을 때만 보여요.
  - effort 선택: 그 모델이 effort를 지원할 때만 보여요.
  - 컨텍스트 사용량 고리: 사용량을 알게 된 뒤에만 보여요.
- **작업 공간 바꾸기:** 첫 메시지 전에는 칩으로 바꿀 수 있고, 써 둔 초안도 같이 옮겨 가요. 첫 메시지를 보낸 뒤에는 세션에 묶여요.
- **모델:** 고르면 그 모델이 새 세션의 기본값이 돼요. 이미 시작한 세션은 자기 로그에 적힌 모델을 계속 써요.

### 2.5 대화 화면

- **한 턴의 순서:** 사용자 말풍선 → 작업 묶음 → 최종 답 → 완료 줄.
  - 작업 묶음은 하는 일로 이름이 붙어요("Reading files", "Running commands").
  - 턴이 끝나면 작업 묶음은 "Completed in …"으로 접혀요. **최종 답은 절대 접지 않아요.**
- **작업 세부 단계:** Compact / Standard / Detailed / Verbose 네 단계가 있고, 언제 접을지도 고를 수 있어요.
- **Show coding view(기본 꺼짐):** 켜면 진행 기록(Trajectory) 탭, 바뀐 파일 카드, 전문가용 프리셋(PTC, Minimal)이 보여요.
- **바뀐 파일:** 턴 끝에 카드로 4줄까지 보여 줘요. 누르면 오른쪽 패널에 diff 탭이 열려요.

### 2.6 승인과 권한

- **승인 요청은 입력창 자리를 차지해요.** 별도 창으로 띄우지 않아요.
  - 맨 위 줄: 주황 점과 "Waiting for approval"
  - 그 아래: 요청 이유 한 줄과 도구 세부
  - 버튼은 [Reject]와 [Allow once] 두 개. Enter는 허용, Esc는 거절이에요.
  - "항상 허용"은 일부러 만들지 않았어요.
- **계획 검토:** [Approve] [Refuse] [Request changes].
- **접근 모드:** Read Only / Workspace Write / Full access 세 가지예요.
  - 입력창에서 고르면 지금 세션에 적용되고, 설정에서 고르면 새 세션의 기본값이 돼요.
  - Full access는 "I understand the risks" 체크를 해야 켜져요.

### 2.7 설정 (모달)

- **왼쪽 메뉴는 네 개뿐이에요:** General / Models / Built-in plugins / Agent presets.
- **Models:**
  - 제공자마다 카드 하나에 API 키 칸 하나가 있고, 나머지는 "Customized settings" 안에 접혀 있어요.
  - 키는 저장만 되고 화면으로 다시 보여 주지 않아요. 이미 넣었으면 "Configured — enter a new value to replace"라고만 떠요.
- **Agent presets:** 프리셋 카드마다 "Set as new task default"와 "View configuration"(읽기 전용 YAML)이 있어요.
- **"Open configuration file":** 고급 설정은 화면을 따로 만들지 않고 설정 파일을 열게 해요. 로컬에서 접속했을 때만 보여요.

### 2.8 시각 체계 (`packages/client/ui-theme`)

- **컴포넌트:** CSS Modules와 자체 primitives를 써요. Tailwind나 UI 라이브러리는 없어요.
- **모양:**
  - 둥글기: 4 / 8 / 12 / 16 / 20, 패널은 28
  - 글자 크기: 13 / 14 / 16 / 18 / 20 / 24
  - 테두리는 0.5px, 글자 굵기는 500까지
- **색:** 파랑(DeepSeek blue) 하나에 상태색으로 초록, 주황, 빨강을 써요. 라이트/다크/시스템 모드가 있어요.
- **문구:** 짧은 문장, 버튼은 동사로 써요. 지우는 확인 창에서는 무엇이 남는지 말해 줘요("The folder and session logs will be kept").

## 3. 구조

### 3.1 프로세스와 플러그인

- **프로세스는 Node 하나예요.** 플러그인끼리는 Cordis 서비스 트리로 묶여 있고 프로세스로 격리하지 않아요. 셸, 코드 실행, 일부 하위 에이전트만 자식 프로세스로 띄워요.
- **플러그인 형태:**
  - 서비스(`ctx.llm`, `ctx.sessions` 등)를 제공하거나, `inject`로 다른 서비스를 요구해요.
  - 모든 등록은 해제 함수를 남겨서 핫 리로드가 안전해요.
- **구성은 층으로 쌓여요:** 번들 → 프로필 `cordis.patch.yml` → 홈 patch → 실행할 때 덮어쓰기. 각 줄은 id로 가리켜서 바꿔요.
  - **설정 화면은 따로 저장소를 두지 않아요.** 같은 patch 파일에 써요.
- **실행 방식:** `dsh` 하나에 프로필만 바꿔서 web, headless, sdk(JSON-RPC stdio), acp로 돌아요.
  - 데스크톱은 Electron 껍데기가 같은 웹 앱을 띄우는 구조예요.
- **웹과 호스트 사이:** `/api` 요청이나 `/api/remote.mux` WebSocket으로 통신해요. 루프백에만 열리고, 실행할 때마다 새 토큰이 붙어요.

### 3.2 세션

- 세션 하나는 추가만 하는 이벤트 로그(JSONL, zstd)예요.
- **"모델이 보는 것 ⟺ 로그에 있는 것":** 모델에 들어가는 대화 기록은 로그에서 만들어요.
- **로그에 같이 남는 것:** 모델, 프리셋, 권한, 승인(물음과 결정 한 쌍) 모두 이벤트로 남아요.
  - 그래서 이어 하기와 포크는 로그를 다시 재생하면 돼요.
- **보관:** 세션 이벤트가 아니라 작업 공간 목록의 상태로 관리해요. 실행 중인 게 있으면 거절해요.

### 3.3 프리셋과 권한

- **프리셋:** 도구, 페르소나, 스킬의 묶음이에요. standard / ptc / minimal / cordis(Creator)가 있어요.
  - 실행 중인 에이전트는 프리셋이 바뀌어도 원래 버전을 계속 써요.
- **권한은 두 손잡이를 프리셋으로 묶었어요:** 샌드박스 범위(read-only / workspace-write / full)와 승인 정책(ask / never).
  - 승인 결과는 정해진 네 가지예요: allowed-once / rejected / cancelled / unavailable.
  - 허용(allowed-once)이 아니면 전부 거절로 처리해요. 승인은 한 번 쓰고 끝나고 기억하지 않아요.
  - 하위 에이전트는 부모가 받은 허용을 물려받지 않아요.

### 3.4 자격 증명

- 설정에는 환경 변수 이름(CredentialRef)만 남아요.
- 값은 요청할 때마다 다시 읽어서, 키를 바꿔도 재시작이 필요 없어요.
- API는 쓰기 전용이에요. `describe`는 `{configured, source, writable}`만 돌려줘요.

## 4. me와 비교

| | dsh | me 지금 |
|---|---|---|
| 화면 구성 | 사이드바 + 대화 하나, 설정은 모달 | 탭 3개(대화/작업/상태) |
| 기다리는 일 | 세션 줄의 시간 자리에 "Approval" | 작업 탭 배지 + 대화 카드 + 작업 탭 목록 |
| 승인 | 입력창 자리에 [Reject][Allow once] | 대화 안의 카드(접힌 칸 2개, 위험 표시, 안내 문장) |
| 세부 정보 | 기본 숨김, coding view로 켬 | 기본으로 보여 줌 |
| 작업 공간 | 빈 세션에서 칩으로 고르고, 보낸 뒤에는 고정 | 입력창의 프로젝트 버튼과 상태 탭 |
| 모델 | 고르면 기본값, 시작한 세션은 유지 | 이 대화 / 기본값 저장 / 기본값 따르기 |
| 권한 | 세션 단위 3단계 + 그때그때 한 번씩 승인 | 위임할 때마다 승인 |
| 설정 | 모달 4칸 + 설정 파일 열기 | 상태 탭에 섞여 있음 + 별도 하네스 화면 |
| 상태·진단 | 사이드바 아래 연결 표시만 | 구성 요소 목록이 화면 맨 위 |
| 프로세스 | Node 하나, 서비스 트리 | 커널 + 플러그인 프로세스(JSON-RPC) |
| 기록 | 세션 로그가 유일한 진실 | 커널 저널 + 엔티티 |

## 5. me에 가져올 것 (제안)

**UX: 가져오면 바로 단순해지는 것**

1. **탭을 없애요.**
   - 화면은 사이드바(대화 목록) + 대화로 바꿔요.
   - 작업 탭을 없애요. 작업 상세는 대화 안 카드나 오른쪽 패널에서 열어요.
   - 상태 탭도 없애요. 내용은 설정 모달과 사이드바 아래 상태 한 줄로 옮겨요.
2. **기다리는 일은 사이드바 줄에서 보여 줘요.** 시간 자리에 "승인", "검토", "답변"을 대신 띄워요. 배지와 작업 탭 목록이 하던 일을 이걸로 대신해요.
3. **승인은 입력창 자리를 대신 차지해요.** "이 작업을 맡길까요?" 한 줄, [거절] [시작] 두 버튼, Enter/Esc 단축키로 줄여요. 요청 내용과 다르게 맡기기는 "자세히" 하나에 넣어요.
4. **세부 정보는 기본으로 숨겨요.** 진행 기록, diff, 실행 도구·모델 고르기는 설정의 "개발자 보기"를 켰을 때만 보여요.
5. **빈 대화 화면에서 바로 시작해요.** 제목 아래 [📁 프로젝트 ▾]와 [⚙ 모델 ▾]를 한 줄로 두고 입력창을 붙여요. 보낸 뒤에는 프로젝트를 대화에 고정해요.
6. **모델은 고르면 그게 기본값이에요.** 시작한 대화는 원래 모델을 계속 써요. 버튼 세 개를 없애요.
7. **설정은 모달 하나로 모아요.** 메뉴는 일반 / 모델 / 실행 도구 / 프로젝트 / 기기 점검이에요. 고급 설정은 "설정 파일 열기"로 넘겨요.
8. **문구는 짧게 쓰고 동사로 끝내요.** 지우는 확인 창에서는 무엇이 남는지 알려 줘요. 보관은 확인 창 대신 되돌리기로 해요.

**구조: 천천히 검토할 것**

1. **세션(대화) 기록에 모델, 프리셋, 권한, 승인 결정까지 이벤트로 남기기.** 이어 하기와 감사(audit)가 쉬워져요.
2. **권한 프리셋(읽기 / 프로젝트 쓰기 / 전체)과 승인 정책을 분리하기.** "프로젝트 쓰기 + 묻기"를 기본값으로 두면, 위임할 때마다 승인하지 않아도 돼요.
3. **설정 화면이 같은 설정 파일 층에 쓰게 하기.** 지금 `me.local.json`과 web.settings 엔티티로 나뉜 걸 하나로 합쳐요.
4. **자격 증명은 참조로만, 쓰기 전용 API로.** me는 이미 대부분 이렇게 하고 있어요.
