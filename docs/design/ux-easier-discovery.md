# me 웹 UX 쉽게 — Discovery (2026-10-11)

scope: extend (기존 시각 시스템 유지: app.css 토큰, 흑백 + 상태색, 점+글자 라벨, 한국어). 바꿀 대상은 흐름·정보 구조·말투.
사용자: 개발자 한 명(소유자). 주로 폰(Tailscale)과 맥 브라우저. 메신저처럼 말 걸고, 위임을 승인하고, 결과를 받아들이는 게 핵심 과업.
증거: `bun run shots` 70장(scratchpad/ux0), 코드 plugins/web/ui (chat/tasks/review/approvals/ops/projects/timeline/shared, 약 4천 줄).

## 핵심 과업 (빈도 순)
1. 말 걸기 → 답 읽기
2. 위임 승인 (하네스 고르기)
3. 결과 확인 → 수락(적용+커밋) / 거절
4. 지금 뭐가 돌고 있는지, 고장 난 게 있는지 보기

## 관찰한 마찰 (스크린샷·코드 근거)
F1. 한 건의 위임이 세 군데에 동시에 뜬다: 대화 목록("확인 필요"), 작업 탭("확인 필요" 버킷), 승인 탭. 배지도 작업 1·승인 1로 같은 일을 두 번 센다. 사용자는 "어디서 처리해야 하지?"를 매번 판단해야 한다.
F2. 대화 안 위임 줄의 "승인하기"는 승인 탭(#/approvals)으로 화면을 옮긴다(chat.tsx:281). 하네스 선택·승인을 대화 안에서 끝낼 수 없다. 결과가 오면 다시 작업 탭으로 가야 수락할 수 있다.
F3. 용어가 내부 구현 말이다: 하네스, local.claude-code, 위임, 워커 보고, diff 새로고침, 적용·커밋됨, 지시 내용·완료 기준, 위험 보통, gjc-head → kernel · approval, 플러그인 brgr/jev/slang/summarize.
F4. 사용자는 한국어로 말했는데 작업 제목은 지시서(영어 brief)로 뜬다: "Inspect the project structure and existing docu…", "Create NOTES.md at the project root…". 자기 요청을 알아보기 어렵다.
F5. 폰 첫 화면이 대화 목록이라, 말을 걸려면 "+ 새 대화"를 한 번 더 눌러야 한다. 메신저인데 입력창이 첫 화면에 없다.
F6. 작업 상세는 메타 표(하네스/프로젝트/시작/걸린 시간)가 맨 위, 결과·변경은 아래. 적용 후 하단 바의 유일한 버튼이 "diff 새로고침".
F7. 탭 5개 중 운영·프로젝트는 매일 쓰는 화면이 아니다. 운영은 플러그인 내부 이름 목록(brgr, jev, slang…)과 "지금 돌고 있는 것"(web → gjc-head · chat.send)이 개발자 디버그용 표현. 프로젝트 탭은 필터 하나의 역할.
F8. 경로 노이즈: "…/T/me-e2e-project-um4yFF"가 대화 목록·작업·승인·상세·입력창 위에 반복.
F9. 승인 카드의 "위험 보통"이 무슨 뜻인지, 승인하면 무슨 일이 생기는지(어느 폴더에서 무엇을 바꾸는지)가 한 줄로 안 보인다. 지시 내용은 접혀 있다.
