# me 웹 UI 단순화 및 UX 개편안

> **기준 시각 시스템 준수**: `app.css` 디자인 토큰 유지, 점+글자 상태 라벨, 상태 표현에만 색상 사용, 라이트/다크 모드 지원, 760px 반응형 분기점, 44px 터치 타깃, a11y 0건 위반 준수.

---

## 1. 대상 사용자, 핵심 과업 (우선순위 순), 단순화의 한 문장 테제

### 1.1 대상 사용자
- **1인 개발자 (소유자)**: 이동 중 스마트폰(Tailscale 경유 브라우저) 및 맥북 데스크톱 브라우저 환경에서 `me`를 개인 개발 OS로 사용.
- **사용 맥락**: 메신저처럼 질문을 던지고 지시하며, 에이전트의 작업 승인 요청을 빠르게 검토하고, 완료된 코드 변경 결과를 확인하여 수락(커밋)하는 흐름이 주를 이룸.

### 1.2 핵심 과업 (우선순위 순)
1. **말 걸기 → 답변 확인**: 즉각적인 대화 및 작업 지시 (빈도 최다).
2. **위임 승인 (도구/하네스 선택)**: 백그라운드 워커 실행 전 위험도 및 실행 도구 확인 후 승인.
3. **결과 검토 → 수락(적용+커밋) / 거절**: 완료된 diff 및 요약 확인 후 메인 코드베이스에 반영.
4. **실행 중인 작업 및 시스템 상태 확인**: 백그라운드 진행 상태 모니터링 및 기기/플러그인 장애 점검.

### 1.3 단순화의 한 문장 테제
> **"메신저 대화방 안에서 일의 시작(말 걸기)부터 승인·진행 확인·결과 수락(적용)까지 끊김 없이 완결하고, 별도 탭은 비동기 작업 관리와 장애 점검을 위한 백로그/대시보드로 역할을 명확히 분리한다."**

## 2. 정보 구조 (IA): 탭 구성 및 승인·수락 흐름 (F1/F2 마찰 해소)

### 2.1 탭 구성: 기존 5개 → 3개 탭으로 통합

| 탭 이름 (영문/라우트) | 역할 및 포함 내용 | 통합 대상 |
| :--- | :--- | :--- |
| **대화 (`/chat`)** | • 메인 홈 화면.<br>• 실시간 대화 및 프로젝트별 스레드.<br>• **인라인 위임 승인** 및 **인라인 결과 수락/거절** 완결. | 기존 `대화` |
| **작업 (`/tasks`)** | • 비동기 백로그 및 작업 아카이브.<br>• 상태별 버킷 (`확인 필요`, `진행 중`, `완료`, `실패/숨김`).<br>• 대화방을 벗어난 전체 작업의 상세 diff 검토 및 수락/거절. | 기존 `작업` + `승인` 통합 |
| **상태 (`/ops`)** | • Mac 및 원격 기기 헬스체크.<br>• 플러그인 정상 가동 여부 및 장애 알림.<br>• 프로젝트 필터 및 환경 설정. | 기존 `운영` + `프로젝트` 통합 |

### 2.2 F1 / F2 마찰 해결 결정

- **F1 해결 (중복 분산 및 이중 배지 해소)**:
  - 독립된 `승인` 탭을 완전히 폐지하고 `작업` 탭의 `확인 필요` 버킷으로 흡수.
  - 배지는 `작업` 탭에 단 1개의 카운트로 일원화 (`승인 대기` + `수락 대기` 합산).
  - 어디서 처리해야 할지 고민할 필요 없이: **"지금 보던 대화방에서 바로 처리"**하거나, **"작업 탭에서 모아서 처리"**하는 2단계로 단순화.
- **F2 해결 (In-thread First 승인 및 수락)**:
  - 대화방의 위임 줄(`DelegationLine`)을 인터랙티브 카드로 강화.
  - 하네스(도구) 선택과 `[승인]` 버튼을 대화방 안에서 바로 제공하여 다른 탭 이동 제거.
  - 작업 완료 시 대화방 카드에 변경 파일 통계(+/-)와 `[변경사항 적용]`, `[거절]` 버튼을 직접 노출.
  - `작업` 탭은 대화 컨텍스트 없이 여러 작업을 모아보거나, 긴 diff를 전체 화면으로 정밀 검토할 때 사용하는 보조 뷰로 정의.

## 3. 화면별 변경사항 (Keep, Remove, Merge, Reorder)

### 3.1 대화 목록 / 새 대화 (Chat List & Composer)
- **유지 (Keep)**: 스레드 제목, 프로젝트 태그, 상대적 업데이트 시간 표시.
- **제거 (Remove)**: 모바일 진입 시 빈 대화 목록만 노출되는 대기 상태 제거, 긴 절대 임시 경로 노출 제거.
- **통합 (Merge)**: 모바일 뷰 첫 진입 시 가장 최근 활성 대화방을 기본 렌더링하거나, 목록 하단에 즉시 입력 가능한 Composer를 고정 노출하여 "새 대화" 버튼 클릭 뎁스 제거 (F5 해소).
- **재정렬 (Reorder)**: 대화 목록 각 항목의 상태 표시를 `[점 + 핵심 상태 단어]`로 우측 상단에 정렬.

### 3.2 대화 상세 및 위임 줄 (Thread & Delegation Card)
- **유지 (Keep)**: 말풍선 렌더링, 실시간 텍스트/도구 스트리밍, 페이즈 라인(PhaseLine) 클릭 시 타임라인 드로어 연결.
- **통합 (Merge)**: 프로젝트 선택 드롭다운을 입력창 상단의 간결한 칩(Chip)으로 최소화.
- **개편 (Reorder)**:
  - 단순 링크였던 `DelegationLine`을 **인터랙티브 위임 카드**로 전환.
  - `승인 대기`: [추천 도구 드롭다운] + [승인 버튼] + [거절 버튼] 인라인 배치.
  - `진행 중`: [점+진행 중] + [도구명] + [경과 시간] 실시간 표시.
  - `결과 도착`: [결과 요약] + [변경 파일 통계 (+12 -3)] + [수락 (적용)] + [거절] + [상세 diff 보기 링크] 제공.

### 3.3 승인 화면 (Approvals)
- **제거 (Remove)**: 독립 네비게이션 탭으로서의 `승인` 화면 폐지.
- **통합 (Merge)**: `작업(/tasks)` 탭의 `확인 필요` 섹션 및 대화방 인라인으로 완전 이관.
- **개편 (Reorder)**: "위험 보통" 같은 시스템 중심 용어 대신 `3개 파일 변경 예정 · 저장소: repoName` 형태로 실제 영향 범위를 요약 첫 줄에 노출 (F9 해소).

### 3.4 작업 상세 및 결과 검토 (Task Detail & Review)
- **유지 (Keep)**: 파일별 변경 통계(+/-), 파일별 diff 아코디언, 문법 하이라이트.
- **제거 (Remove)**:
  - 화면 상단을 차지하던 거대한 메타 정보 테이블(하네스, 프로젝트, 시작 시간, 소요 시간).
  - 적용 완료 후 하단 바에 남는 무의미한 `diff 새로고침` 버튼 (F6 해소).
- **재정렬 (Reorder)**:
  - 1순위: **작업 결과 요약(워커 보고)** 및 **변경된 파일 diff / 통계**를 최상단 배치.
  - 2순위: 하단 액션 바 (`[변경사항 적용]`, `[거절]`).
  - 3순위: 세부 메타 정보(실행 도구, 작업 ID, 원문 지시서)는 하단 `상세 정보` 접기(fold) 영역으로 이동.

### 3.5 상태 및 운영 (Status / Ops)
- **유지 (Keep)**: 기기별 헬스체크 (`이 Mac`, 원격 노드), 이상 감지 시 배지 및 경고 표시.
- **제거 (Remove)**: 개발자 디버그용 내부 플러그인 목록(`brgr`, `jev`, `slang`, `summarize`), 원시 op 문자열(`gjc-head -> kernel`) 나열 (F7 해소).
- **통합 (Merge)**: 프로젝트 목록 관리를 상태 탭 내 '등록된 프로젝트' 섹션으로 통합.
- **개편 (Reorder)**: "모든 시스템 정상 작동 중" 또는 "1개 서비스 점검 필요" 식의 직관적인 사용자 중심 요약 카드 최상단 배치.

## 4. 용어 사전 (Current Term → Plain Korean Term)

내부 구현 및 프로토콜 용어를 사용자의 멘탈 모델에 맞는 자연스러운 한국어로 전환:

| 현재 내부 용어 (F3) | 변경할 쉬운 한국어 | 맥락 및 사용 화면 |
| :--- | :--- | :--- |
| **하네스 (Harness)** | **실행 도구** (또는 **도구**) | 승인 카드, 작업 상세, 모델/에이전트 선택기 |
| `local.claude-code`, `local.codex` | **Claude Code**, **Codex** | 도구 선택 옵션 라벨 (`local.` 접두사 제거) |
| **위임 (Delegation)** | **작업 맡기기** (또는 **작업**) | 대화방 내 위임 카드, 작업 생성 알림 |
| **워커 보고 (Worker report)** | **작업 결과** | 작업 상세 화면의 결과 요약 섹션 제목 |
| **적용·커밋 (Apply & Commit)** | **변경사항 적용** (또는 **수락 (커밋)**) | 작업 리뷰 하단 액션 버튼 |
| **diff 새로고침** | **새로고침** | 변경 확인 중일 때만 노출 (완료 후 제거) |
| **지시 내용 / 완료 기준** | **요청 내용 / 완료 조건** | 승인 카드 및 작업 상세 접기 영역 |
| **위험 보통 / 위험 낮음 / 위험 높음** | **코드 수정 (보통) / 단순 조회 (안전) / 파일 삭제·외부 전송 (주의)** | 승인 카드의 리스크 배지 |
| **플러그인 목록 (`brgr`, `jev`, `slang`)** | **백그라운드 작업기, 기억 동기화, 요약기** (또는 내부 숨김) | 상태(운영) 탭 |
| `sealed` | **검토 대기** | 작업 상태 라벨 (결과 도착 후 수락 대기 중) |
| `applied` | **적용 완료** | 작업 상태 라벨 (커밋 반영 완료) |
| `needs` (확인 필요) | **확인 필요** | 승인 및 결과 검토 대기 버킷/라벨 |

## 5. 작업 제목 생성 규칙 및 경로 표시 규칙

### 5.1 작업 제목 생성 규칙 (Task Title Source) (F4 해소)
- **규칙 1 (사용자 원문 우선)**:
  - LLM이 내부적으로 생성한 영어 지시서(`brief`) 대신, **사용자가 실제로 입력한 최초 메시지(`gjc-head message.text`)**를 작업 제목으로 사용 (`task.origin.messageId`로 매핑).
  - 예: `"Inspect the project structure..."` ❌ ➔ `"웹 UX 단순화 작업 진행해줘"` ⭕
- **규칙 2 (문장 길이 축약)**:
  - 원문 메시지가 긴 경우, 첫 번째 줄 또는 최대 40자까지 표기하고 말줄임표(`…`) 처리.
- **규칙 3 (영어 Brief의 위치)**:
  - 시스템이 생성한 영문 지시서 및 완료 기준(`criterion`)은 제목이 아닌 작업 상세의 `요청 내용 접기(fold)` 내부에 보조 정보로 표시.

### 5.2 경로 표시 규칙 (Path Display Rules) (F8 해소)
- **규칙 1 (저장소/프로젝트명만 표시)**:
  - `/private/var/folders/.../T/me-e2e-project-um4yFF`와 같은 긴 절대 경로 및 임시 폴더 경로를 UI 본문에 직접 노출하지 않음.
  - 폴더명의 마지막 세그먼트(`repoName(path)`)만 추출하여 `📁 my-project` 형태의 칩으로 표기.
- **규칙 2 (임시/테스트 프로젝트 단순화)**:
  - 임시 경로의 경우 `📁 임시 프로젝트 (um4yFF)` 등으로 짧게 정제.
- **규칙 3 (전체 경로 접근성)**:
  - 전체 절대 경로는 태그 호버 시 툴팁(`title` 속성)이나, 상세 보기 접기 영역에서만 필요 시 복사할 수 있도록 배치.

## 6. 스크린샷으로 검증 가능한 인수 기준 (Acceptance Criteria)

1. **대화방 이탈 없는 위임 승인**:
   - 대화 스레드 안의 위임 카드에서 도구(하네스) 선택 드롭다운과 `[승인하고 작업 시작]` 버튼이 직접 노출되며, 클릭 시 승인 탭으로 화면이 전환되지 않고 그 자리에서 즉시 실행 상태로 바뀐다.
2. **대화방 이탈 없는 결과 수락**:
   - 작업이 완료(`sealed`)되면 대화방 내 카드에 변경 파일 요약(`+N -N`)과 `[변경사항 적용]` 버튼이 노출되며, 클릭 시 즉시 `적용 완료` 상태로 전환된다.
3. **탭 바 3개 및 배지 단일화**:
   - 하단(모바일) 및 사이드(데스크톱) 네비게이션이 정확히 3개 탭(`대화`, `작업`, `상태`)으로 렌더링되며, 승인 대기와 결과 검토 대기가 `작업` 탭의 단일 `확인 필요` 배지 숫자로 합산된다.
4. **한글 사용자 질의 제목 렌더링**:
   - `작업` 목록 화면에서 작업 카드의 메인 타이틀이 영문 `brief`가 아닌 사용자가 입력한 한글 질의 문장으로 표시된다.
5. **결과 우선 작업 상세 레이아웃**:
   - 작업 상세 화면 진입 시 상단에 메타데이터 테이블 대신 `작업 결과 요약`과 `파일별 diff`가 1순위로 표시되고, 하단 바에 `diff 새로고침` 대신 명확한 `[변경사항 적용]` / `[거절]` 버튼만 노출된다.
6. **경로 노이즈 제거**:
   - 모든 화면(대화 목록, 작업 카드, 헤더)에서 30자 이상의 긴 절대 경로가 사라지고 간결한 프로젝트 칩(`📁 repo-name`)으로 대체된다.

## 7. 파워 유저를 위한 리스크 및 해결 경로 (Risks & Escape Hatches)

| 잠재적 리스크 / 상실 요소 | 파워 유저가 여전히 접근할 수 있는 경로 (Escape Hatch) |
| :--- | :--- |
| **세부 op/트레이스 로그 숨김** | 대화창의 상태 페이즈(`PhaseLine`) 클릭 시 기존의 `TraceDrawer`(타임라인 드로어)가 열려 raw 커널 op 및 도구 입출력 전체 확인 가능. |
